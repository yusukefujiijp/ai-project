# 定期Ark Mapと限定save

## 1. 何を引き受けるか

[dot-0000: 初穂](../actors/dot-0000/README.md)が、確認できたArkの現在地を定期的にHumanへ返し、その過程で見つかった意味のある差分を、承認済みの担当原本へ保存する。本書は、このDotの定期Mapと限定saveの単一の運用原本である。全Dotsの共通Runtimeや全会話の保管庫にはしない。

現在の承認済み予定は **04:00／08:00／12:00／16:00／20:00 JST（Asia/Tokyo）**。実際の予定、実行状態、接続の成否は製品側で確認する。本書の保存は予定の作成・変更・実行成功を証明せず、内部の予定IDや秘密情報を公開原本へ記載しない。

目的は、Humanが情報を探し、分類し、GitHubとWorkの状態を照合し、文脈を組み立て直す負担をAI側で引き受けること。必要な説明・洞察・比較材料・具体例を短縮せず、情報の役割と配置を安定させる。更新件数や短さ自体を成果にしない。

- 現在地の復元、Tree、Node & Edge、Evidenceの区別は [$map-ark-current-positionスキル](../../skills/map-ark-current-position/SKILL.md)

各本文をここへ複製せず、現行の原本を使う。本書は定期実行固有の表示・読取・保存境界を所有する。RuntimeにSkillがあること、共有原本を読んだこと、実際に適用・実行できたことを分ける。

## 3. 一回の実行で行うこと

1. 本書の現行版と、このDotの最新のHuman指定・Correction・Plan-only・STOPを確認する。開始時の意図だけで続行せず、書込直前にも影響する新しい指定がないか確かめる。
2. 今回の範囲に必要なSourceを取得する。[Dots入口](../README.md)、[共通lessonsの契約](../lessons/README.md)と関連lesson、存在して適用される専門lesson、選択したArk原本・実際の会話を読む。指定された全文・順序・Identity・Binding・EOFは守る。
3. 共有Map Skillで、目的・担当・枝の状態・現在地・未接続の意味を復元する。GitHub保存事実、実際に取得したWork会話、Human報告、AIの解釈を分け、読んでいない範囲まで網羅済みにしない。
4. 保存候補を既存の担当原本と比較する。新規作成・既存更新・参照のみ・NO_CHANGE・意図的保留から選び、§5の承認内で意味のある差分だけを保存する。保存先固有の検査、revision条件、Remote再取得まで行う。
5. 確認できた現在地と保存結果を反映し、§4の順序でMapを返す。保存失敗・保留は必要な範囲で示し、確認できるMapの提供まで一律に止めない。

各回で必要な現行Sourceを確認し、同じアクセス可能な文脈で確認済みかつ変化のない読解は再利用する。全Repository・全履歴・全Skillの反復読込、毎回の新lesson作成、全出力の一律保存はしない。前回を取得できなければ差分を創作しない。

前回Mapの時刻は、保存済み範囲の打切り時刻ではない。前回までに未確認・未保存だった意味のある候補も、既存原本・実際の保存結果・現在の権限と照合し、見落としたまま直近の差分だけへ絞らない。

## 4. Humanへ返すMapの配置

### 冒頭とヘッダー

先頭行は **【Ark Map現在地: 今回の実際の洞察】**。半角コロンと半角スペースを使い、洞察は今回の根拠に忠実な結論・発見・現在地を入れる。未確認の成果をTitleへ載せない。

その直下に、次の七行のラベルと順序を固定する。値は各回の実際の確認結果で埋める。

```text
現在: YYYY-MM-DD HH:MM（日本時間）
対象日: YYYY-MM-DD
場所: 仙台
日の出: HH:MM
日の入り: HH:MM
現在の天気: …
明朝の天気: …
```

「現在」は今回実際に確認したJST日時、「対象日」はそのJST日付とする。日の出・日の入りは対象日の仙台の値を使い、それぞれ確認した出典へリンクする。場所は仙台を対象地点として示し、Humanの現在の所在地を推定した表示にはしない。

現在の天気は観測を優先し、観測時刻を添える。予報しか取得できない場合は「現在の天気: 現在の予報（対象日時）…」と明示する。明朝の天気は、翌日の年月日と実際に取得した早朝の予報時間帯を添える。天気の各値からも出典へ戻れるようにし、現在時刻・観測時刻・予報の対象時刻を混ぜない。

予定上の起動時刻を現在時刻として代入しない。日付跨ぎも実際のJSTを基準にする。取得した時間単位・精度を保ち、時間帯予報から特定の一分間や日の出時刻ちょうどの天気を確認したように書かない。取れない値は「未取得／未確認」とし、古い値・推測・近隣地点を黙って代入しない。一般的な県庁所在地定義や国立天文台の定型注意書きを毎回添えず、今回の数値の解釈を変える制約だけ説明する。

### 本文の固定順序

ヘッダーの後に区切りを置き、次の見出しをこの順で使う。

- **【今回の要点】**：前回からの重要な変化、新しい確認、今回も重要な不変点を、今回判断できる根拠から示す
- **【GitHub側のMap】**：今回取得したRepositoryの保存事実と、その確認時点・Sourceを示す
- **【ChatGPT Work側のMap】**：実際に取得できた会話から分かる現在地を示す。会話を取得できなければ、その範囲は未確認とする
- **【Living Review】**：二つのMapの関係、Bottleneck、残る価値・Unknownを読み、今回の判断と理由を示す
- **【Next step】**：直前のLiving Reviewから、今つなぐ先・理由・成立条件を示す最終節

Tree（枝＋状態＋現在地）とNode & Edgeを使い、どちらのMap・どの範囲・時点を表すか明示する。Node名・状態・根拠を対応させ、Edgeには接続先と関係の意味を書く。GitHubとWorkを一つの未分化な一覧に混ぜず、両者間の接続は出所を保って説明する。

GitHubに保存済みでもWork側で受け取ったとは限らず、Workの発言があってもGitHub更新済みとは限らない。取得できた会話だけを根拠とし、現在の会話一覧・Thread名・検索snippetだけから全会話の内容を把握したとしない。

末尾は **【Living Review】→【Next step】** を隣接させ、その後に別のまとめ・参考資料節を置かない。Sourceリンクは関係する本文へ置く。実行・確認・比較・維持・意図的保留・今回完了はいずれもNext stepになり、Mapのために新Taskや無根拠の発見を作らない。

## 5. このDotに承認された継続save

### 入力と、書込先の境界

対象は、このDotの現在の会話で提供されたArk協働の内容と、実際に取得した公開Ark原本から得る、保存価値のある成果・訂正・根拠・再開文脈。読取可能なSourceであることと、その内容を外部へ保存・公開できることは別である。

当初の保存先は次に限定する。既存の形式・追記／訂正・必須field等は各所有先の契約に従い、本書で置き換えない。

| 保存する意味 | 承認済みの保存先と所有契約 |
|---|---|
| AI活用の一区切り・重要な差分 | `records/YYYY/MM/YYYY-MM-DD.jsonl`。[records契約](../../records/README.md)に従い、記録時点のAsia/Tokyo日付を使う |
| dot-0000自身の仕事・観測・回復の経緯 | `dots/logs/dot-0000.jsonl`。[logs契約](../logs/README.md)に従う。実在するtask_id等を補えない時に架空値を作らない |
| Dots全体へ共有できる再利用可能な学び | `dots/lessons/lessons.jsonl`。[lessons契約](../lessons/README.md)に従う |
| 全Dotsへの一般化では誤適用される、定期Map固有の実際の学び | 必要が生じた時だけ `dots/ark-map/lessons.jsonl`。共通lessons契約のschema 2・読取・更新・Sourceを再利用し、相対locatorはこの実ファイル位置から解決する |

専門lessonの空ファイルを予約作成しない。著者が初穂であることだけでは専門化しない。同じ目的・意味のlessonは一つの担当原本へ置き、共通lessonと専門lessonを同期コピーしない。

各Topic原本やBoardへは、保存する内容と具体的なpathについて既に明示承認がある場合だけ進む。この定期saveの承認から、新しいTopic原本への書込権限やBoard送信権限を導かない。その他の保存先は必要な差分の承認を得るまで保留する。

ChatGPT長期メモリ、非公開Work会話・別会話の内容を、この委任による転記・バックアップ・同期の対象にしない。Mapで参照できた私的資料を公開保存へ自動転用しない。秘密情報や権限外の第三者情報も公開しない。

### 差分の判断と保存確認

既存原本で必要な意味と根拠が回復できれば **NO_CHANGE** は正当な完了である。同じ出来事をrecords・logs・lessonsへ機械的に三重化せず、それぞれに独立した役割がある時だけ必要な意味と参照を残す。Map全文・天気予報・全Tool操作の恒久アーカイブは作らない。

書込直前に対象の最新版とSHA等のrevisionを取得し、既存行・未知field・順序・他AIの変更を保持する。利用できる版条件で保護して順次保存し、各対象をRemoteから再取得して意図した差分と保持内容を照合する。依存する次の書込は前の再取得を終えてから行う。

競合・Timeout・応答欠落では保存失敗と決めつけず、ID・本文・版・履歴を先に照合する。正常部分だけの再生成、盲目的な再送、新IDでの二重追加はしない。保存先契約に従って安全に再開できなければ、その書込を保留する。

承認済みの同じ対象・目的・範囲での通常の保存判断・必要な検証には再承認を課さない。今回の委任は、本書自身の権限拡張、AGENTS等の全体方針・共有Skillの改訂、新Task開始、外部送信、Reset、予定変更を承認するものではない。

## 6. 止める範囲と検証の境界

最新のHuman指定・Correction・STOP、必須Source、本書の現行版を取得できない場合は、書込を行わないread-only fallbackに戻る。分かる範囲のMapを返し、未確認の範囲と書込を再開するための条件を示す。未取得を「STOPなし」と解釈しない。

現在のPlan-only・会話内だけ・保存STOPは、同じ対象の背景saveにも適用する。全面STOPならその範囲を守り、Map出力も禁止されていれば返さない。無関係な承認済み作業まで一律に止めず、影響範囲を区別する。

保存に失敗しても、根拠を持って示せるMapは提供できる。逆に、Mapを返せたことは保存成功の証拠ではない。文書整合・Remote保存・製品予定への接続・実際の各回の実行・Humanへの到達・生活上の効果を別々に確認し、未観測の段階を完了としない。
