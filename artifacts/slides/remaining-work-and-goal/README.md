# 残作業とGoal

**残作業をGoal・状態・担当・再開条件と結ぶ意味を、五枚の流れで読み直すための制作資料。**

[Slides入口](../README.md)の保存・公開・検証境界に従う。本書は公開原本から再制作できる説明を所有し、個々の案件の現在状態や会話全文を保管する台帳にはしない。

## 目的と表現

作品の題は「なぜ『残作業とGoal』がArkの中心になったのか」。これは協働における価値を読み解く編集上の問いであり、全利用者への有効性や長期効果の実証を意味しない。

主な用途は、自分の協働を振り返り、何が次の判断を助けるかを理解し直すこと。日本語の大きな文字とページの順序を使い、関係の意味を保つ。複数Threadの現在の残件を毎回スライドへ複製しない。

## 五枚の構成と再制作用本文

### 1. 並列協働と、状況を組み立て直す負担

複数の仕事が進むと、履歴を探し、保存先と会話を照合し、何がまだ必要かを組み立て直す作業が生じる。Mapは、この確認をAIが引き受け、Humanが判断へ戻れるようにする。

根拠：[定期Ark Map §1](../../../dots/ark-map/README.md#1-何を引き受けるか)。負担の軽減は目的であり、測定済みの削減率を示さない。

### 2. 残る仕事へ戻れる入口

残件の重要な変化を、Goal・担当・再開条件とともに伝える。公開運用原本には、自発的な差分報告へのHumanの評価と、意味のある変化だけを届ける試行が記録されている。

根拠：[定期Ark Map §9](../../../dots/ark-map/README.md#9-残作業とgoalの補助確認--意味のある変化だけ届ける)。初期の好評価と長期の有効性を分ける。

### 3. Goalと結ぶと、次の判断が変わる

残作業は、現在のGoalへ至るためにまだ必要な仕事。作業名だけでなく、到達したい状態、いま残る理由、担当、再開条件を見る。

完了済み・不要化した仕事を外し、判断待ち、依存先待ち、任意候補、観察事項を区別する。準備の完了と実利用効果の未確認も別に扱う。

根拠：[map-remaining-work](../../../skills/map-remaining-work/SKILL.md)。この整理から実行権限は生じない。

### 4. 準備完了と、受入れの確認

歴史的な例として、2026-10-17のArk27:09から10への準備記録を使う。固定版の10 Stateでは、Sourceの準備とTarget自身の再構成を分けている。

- 準備側：10の文書を編成した状態。
- 受入れ側：10自身の再構成は準備元から未観測。
- 判断上の意味：準備をやり直すかどうかと、受入れを確認するかどうかは別の問い。

`target_reconstructed: false` は、その固定版では未観測を意味し、受入れ失敗の証拠ではない。現在の残件を示すスライドとして再利用する場合は、後続の担当原本と実際の状態を改めて確認する。

根拠：[固定版10 State](https://github.com/yusukefujiijp/ai-project/blob/aaf6e1dd0cfcaaba8b22b0c3c1e8839c01457d6d/ark-project/ark27/ark27-10/state.json) の `progress`。本書は移行の実行・受入れを代行しない。

### 5. 今ある価値と、これから確かめる効果

公開原本に残るHumanの評価を尊重しつつ、長期の負担軽減や全環境での再現性は別に扱う。
