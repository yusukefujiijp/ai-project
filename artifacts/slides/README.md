# Slides

**スライド作品を、目的と根拠を保って制作・見直し・再制作するための入口。**

[Artifacts](../README.md)の公開範囲・原本分担・保存境界を継承する。ChatGPT Slidesを最初の検討対象とするが、特定AIやサービスへの固定、全回答のスライド化はしない。

## 使いどころを判断する

複数ページの順序と視覚表現が、説明・振り返り・比較・判断を助ける場合に選ぶ。外部への発表だけでなく、Human自身が理解し直す用途も含む。文章や会話内の可視化の方が適する場合は、その方法を選べる。

Current Requestから、誰が何を理解・判断できるようにしたいか、使う場面、資料、作成・保存・共有の範囲を解決する。ページ数やデザインは目的に合わせて選び、Humanへ詳細仕様の作成を必須にしない。Plan-onlyでは調査・計画までに留める。

## 作品ごとの置き方

制作・保存が承認された作品は、原則として安定した短い名前の作品フォルダにまとめる。最初は作品README一つでよく、次のうち再開に必要な内容を残す。

- 目的・対象読者・利用場面。
- 採用した構成・重要な本文・表現意図。
- 根拠の所在と確認時点。引用、Human報告、AIの見立て、未確認の区別。
- 実物の所在・版・形式と、公開可能な範囲での接続情報。
- 実際の確認結果、採用したFeedback、再制作で保持する意味と残る条件。

これは必須欄を毎回埋めるフォームではない。outline、script、sources、feedback等を機械的に別ファイルへ分割せず、素材ファイルや書き出しは実際に必要になった時に加える。作品一覧も実在するものだけを案内し、未作成Pathへのリンクを置かない。

## 制作資料・実物・書き出し

- **GitHubの制作資料**：公開可能な目的・構成・本文・根拠・再制作条件を保つ。
- **サービス上の実物**：その環境で閲覧・編集するスライド。実際の保存先と利用可否を確認する。
- **書き出しファイル**：共有・移送・保全などの必要がある場合に作る。実物との対応と、確認できた再現範囲を示す。

三者の自動同期は前提にしない。GitHubのMarkdownだけで、レイアウト・画像・コメント・操作性を完全に復元できるとは保証しない。重要な意味の修正を採用した時は、現在の承認範囲で制作資料との不一致を解消する。見た目の全変更を二重管理する義務にはしない。

ChatGPT Slidesなど、利用する環境の現行の公式手順・実際の機能を確認する。特定の製品やプラン名だけで作成能力を認定しない。依頼された経路が使えない場合は制約と代案を示し、別形式の生成をその製品での成功と呼ばない。

## 確認とFeedback

内容の正確さ、文字や図の可読性、欠落・はみ出し、根拠への接続を、実際に利用できる表示経路で確認する。iOS等の利用端末が指定されていれば、その読取りや操作に合わせる。確認していない端末での成功は主張しない。

生成・保存、AI側での表示確認、Humanの端末での閲覧・操作、理解や判断への効果を分ける。書き出した場合は、その形式で確認した範囲も区別する。

Feedbackでは、見栄えだけでなく「何が理解しやすくなったか」「何が邪魔だったか」を制作判断へ戻す。文章の方がよいという結果も有効な学びであり、毎回の改訂や新作品を義務にしない。
