# Lifestyle — 生活領域の入口

本人の生活に関わる実践・工夫・経験を、担当する領域の原本へつなぐ案内口。配下に置くことはテーマの重要性や独立性を下げる意味ではない。現在の依頼に必要な入口だけを選び、生活全体の再読や新たなTask開始を必須にしない。

## 領域を選ぶ

| 領域 | 何を育てるか | 現行入口 |
|---|---|---|
| chocoZAP | Sweet Spot、来館、方法の工夫、学習・分析を、本人の経験と訂正から継続して育てる独立テーマ | [chocoZAPのREADME](chocozap/README.md) |

## 接続と役割

Project設定や配布済みSkillなど、Repositoryとは別に更新される入口からは、このmainのREADMEで対象領域の現行入口を解決し、領域READMEが案内する正本へ進む。内部の保存場所が変わる時はこの案内を整え、重量や個別データファイルの住所を外部設定へ複製しない。同じRepository内の必要な直接参照や、版を固定した証拠リンクまで一律に経由させるものではない。

本人の報告、方法・想起メモ、分析・根拠は各領域の担当原本が所有する。共通手順は[Skills](../skills/README.md)、定期実行の指示は[Schedules](../schedules/README.md)が所有する。本書への記載だけで、Project設定・Skill導入・Task設定・実配信が変更済みになるわけではない。

Current Humanの目的・Correction・STOPと、対象に適用される読取・保存の契約を保つ。取得済みで変更のない読解は再利用できる。入口や正本の取得失敗を理由に、旧資料や準備ブランチを現在値・現行保存先へ自動的に置き換えない。未確認の範囲を示し、独立して可能な協働を続ける。

この入口の初版は、承認されたchocoZAP移設に必要な案内を整える範囲。生活領域全体の分類・運用を確定するものではない。[PR #8](https://github.com/yusukefujiijp/ai-project/pull/8)で目的・切替・確認範囲を辿れる。配置や接続方法も、今後のHuman Feedbackと権限に応じて改善できる。
