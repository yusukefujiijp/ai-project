# Usage Token Reset

Human が知らせた Work/Codex の利用枠リセットクーポンを、取り違えや失効、二重実行を避けて扱う。必要な確認と対応だけを選び、以下を一律の全手順にしない。

現在の Root / Teshuvah / Human Guard と Human の最新意図・許可を優先し、この Skill 自体を操作権限にしない。

## 報告と許可を分ける

- 付与報告は、対象・期限・次の選択を整理する入口とする。報告だけを使用、予約、継続監視の包括許可にしない。
- 「手動で使った」は Human の報告として受け取り、UI で確認できた事実と区別する。報告を無視して再使用しない。
- 調査・相談・Plan Mode なら確認と提案に留める。実行は今回または既存の明示的な許可の対象・条件・期限内で行う。
- 新規付与を毎日探索する監視、別クーポンの代用、購入・アップグレード・dot 側のリセットへ広げない。

## 対象と期限を確かめる

必要に応じて、Human の報告、現在の Usage UI、既存の通知・自動実行を照合する。

- アカウント／ワークスペース、クーポン種別と効果、残数、正確な失効日時とタイムゾーンを確認する。識別子があれば使う。識別子がなく複数候補を区別できなければ、確定した扱いにしない。
- 日付だけの表示から、その日の終わり（23:59 や翌日 00:00）まで有効とは推定しない。詳細画面で日付・時刻・タイムゾーンを照合し、確認できない部分を明示する。
- 週次の自動回復時刻と、保存済みクーポンの失効日時を混同しない。無料の保存済みリセットか、即時適用された自動／全体リセットかも区別する。
- 現在の利用状況と回復予定を見て、使用する意味と時期を判断する。残量・期限・対象個体を Skill 本文へ固定しない。
- 既存タスクはタイトルだけでなく、本文のアカウント、種別、期限、識別子などで対象を照合する。重複した新規予約を作らない。

Usage の入口は [Settings → Usage](https://chatgpt.com/settings/usage?tab=overview)。URL や過去のラベルを固定セレクターとして扱わず、現在の画面で辿る。

仕様の判断には [OpenAI の banked reset 公式説明](https://help.openai.com/en/articles/20001498) と現在の対象表示を使う。Full banked reset は 5 時間枠と週次枠を回復し、次の週次リセット日も変えるため、元の週次回復日がそのまま残る前提で提案しない。対象枠が一つも回復しなければ消費されない場合があるので、全枠が満杯でも消費のために無意味な作業を発生させない。

## 許可された対応を完了する

### 使用・予約

使用直前にも対象、期限、現在の利用状況、許可条件を照合する。対象を区別できない、既に使用済みらしい、条件が変わった場合は押さずに確認する。残量に関係なく使用する承認があれば、残量があることだけを理由に先送りしない。

予約を作成・変更する許可がある場合は、対象照合、実行日時とタイムゾーン、許可された条件、成功確認、停止条件をそのタスク自体に残す。失効日時と予定実行日時を分け、予定時刻どおりの起動を保証できるとは扱わない。Skill が利用できない実行環境でも安全に動ける自己完結した指示にする。既存タスクを Skill 参照だけへ置換したり、Skill の導入だけを理由に自動改稿・削除したりしない。

クリック結果が不明なら、まず Usage とクーポン状態を再読してから再試行を判断する。残量表示だけで消費成功と断定せず、対象の消費状態・回復表示・更新された回復予定などを合わせて確認する。

許可済みの実行は、成功、失効、Human の STOP、またはアクセス・権限などの解決できない阻害まで扱う。再試行は有効期限と許可された実行条件の内側に収め、状態を見ずにクリックを反復しない。回復可能な一時障害を完了扱いにしない一方、無制限の連打や新しい日次監視を作らない。

### 手動使用後の整合

対象に一致する通知・自動実行だけを、現在の許可範囲で修正・解除する。変更の許可が不足していれば、対象と必要な変更を短く尋ねる。別のクーポンや無関係な予約には触れない。

報告は「Human が使用を報告」「UI で使用を確認」「予約を作成／変更」「未確認／阻害」「失効」など、実際に成立した状態が分かるようにする。実行や予約を確認できていないのに完了と伝えない。

## 短い利用例

- 「リセットクーポンをもらった」→ 対象・期限・現在の利用状況と既存予約を必要な範囲で確認し、次の選択を示す。使用許可は別に扱う。
- 「さっき手動で使った」→ 報告を受け止め、必要なら UI と一致する予約を照合し、許可された変更だけを行う。
- 「この無料 Full reset を、確認した期限の少し前に自動で使って」→ 正確な対象・日時・条件を固め、重複を避けて自己完結した単発予約を作り、設定を検証する。
- 「Plan Mode で失効前の使い方を考えて」→ 利用状況と週次回復への影響を調べ、案を示す。使用・予約変更はしない。

他サービスへの拡張は実際に必要になった時に、そのサービスの仕様と許可条件を確認して追加する。現時点で汎用監視、専用台帳、スクリプトは作らない。
