# Relational Discovery Operations

Run only the operations that can change this answer.

## Bridge

Which node connects purpose to action, candidate to Reality, or observation to learning?

## Cut edge

Which single relation, if broken, stops fruit from reaching Reality even when many upstream nodes look good?

## Hub and dual-center

Are two strong semantic centers both trying to occupy the Human foreground?

## Activation asymmetry

The most important node is not always the node that should stay constantly activated in Human attention.

## Phase

Does the same keyword play different roles before, during, and after action?

## Feedback

How does an actual result change the next candidate, guard, or path priority?

## False dependency

Is one branch waiting on another branch whose output it does not actually consume?

## Folded criteria

Can valid extra criteria stay in the background so the Human foreground keyword count does not rise? Folding is separation of attention, not deletion.

## Fruit Gate

Ask — would a plain node list have produced this insight?

If yes, you have ordinary sorting or a tree. If no, and the insight needed interaction, multi-hop path, bridge, cut edge, hub, feedback, phase change, activation switch, guard boundary, branch friction, or prediction-error update, you have a graph-native fruit candidate.

Pictures, node counts, decimal weights, and graph jargon are not fruit.
