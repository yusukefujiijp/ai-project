# Table Families

Families help you notice which relation view is needed. They are not a menu you must cycle for novelty, and not a catalog to freeze after one success.

Keep one primary graph question even if you borrow columns from two families.

## A. Current coordinate

Use when status and evidence boundary must be shared, or when active versus deferred branches matter.

## B. Node activation

Use when active / dormant / deferred / pruned changes the move, or when importance and constant activation are being confused.

## C. Typed edge

Use when source, relation type, and target direction are the thing being misunderstood.

## D. Path / bridge

Use when two good nodes exist but passage fails, or when purpose-to-action traffic must be checked.

## E. Cut edge / bottleneck

Use when upstream quality never becomes fruit because one relation is broken.

## F. Graph diff

Use after Human material correction, or when before/after path status changed.

## G. Evidence boundary

Use when Confirmed, Candidate, and Unknown are being blended, or when source fact, Human observation, and AI synthesis must be split.

## H. Prediction / Actual / update

Use only when Actual Trace exists. Do not use this family to fake a Living update.

## I. Phase relation

Use when the same node changes role before, during, and after action.

## Schema rule

Ask which fields answer the graph question.

Identity — node, layer, role  
Relation — source, typed edge, target, path, bridge, cut edge  
State — active/dormant, before/after, connection status  
Evidence — Confirmed/Candidate/Unknown, source, Actual Trace, disconfirmation  
Interface — Human meaning, decision impact, correction point

Delete the rest.
