# Pattern Lifecycle

## Data states

Generated — a table appeared. Usefulness is not proven.  
Feedback-paired — Human understanding, friction, correction, or assent attached to that table. This is the field-evidence candidate.  
Retained — Human-approved keep in a place future AI can reuse. Presence in one chat is not persistence.  
Formed — multiple samples, at least one failure sample, context difference, and Human correction have passed.

The learning unit is the table–Human feedback pair, not the table instance.

## Natural feedback is valid

Examples — easy to see; nodes visible but edges weak; current place became obvious; too many columns; this order reads better; the table stopped the prose; keep this diff.

Translate that language into a relation-update candidate. Do not invent a numeric score on top of the Human's words.

## No automatic promotion

Do not save from one positive reaction.  
Do not call a pattern best practice without Human review.  
Do not self-score your own tables into a canon.  
Do not treat novelty as usefulness.  
Do not keep every instance.  
Do not force a saved pattern onto every later context.

This skill ships without a pattern catalog. Grow evidence in ordinary answers first.

## Formation clock

Dialogue moves every turn. Formation stays slow.
