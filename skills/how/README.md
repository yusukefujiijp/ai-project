## 1. 何のためのSkillか

日常・現実世界の対象が、どのように働き、どんな条件やつながりによって現在の状態になるのかを、根拠から理解するためのSkillである。

生活上の場面、物の使われ方、人と道具の関係、仕事の受け渡しなどを主な対象とする。コードも対象にできるが、コード向けの手順へ生活例を付け足す構成にはしない。

目指す成果は、Humanがその場面を捉え、自分の問いを考え、判断できる説明である。現在の依頼が方法の比較や提案まで含む場合は、その成果まで扱う。理解そのものが目的なら、行動計画を付けずに完了できる。

制作過程にも目的がある。対象の切り出し方、根拠から言える範囲、調べるべき不足、説明の終え方を具体化することを通じて、現実を理解する方法をHumanとAIが学ぶ。その学びと、完成後のSkillの有効性が実証されたことは区別する。

## 2. 自然な入力から何を受け取るか

Humanが最初から対象・目的・条件を整理した質問を書くことを前提にしない。

AIは現在の発言と継続文脈から、経験を受け取ること、仕組みを説明すること、方法を比較・提案することのうち、何が必要かを判断する。複数を組み合わせてもよい。

ただし、自然な入力を受けられることは、すべての経験報告を調査へ変えることではない。単独の報告なら受領で十分な場合があり、同じ報告でも継続中の調査へ届いた場合は理解を更新する材料になる。

対象の解釈が回答を変える時は、AIが暫定的に何を扱おうとしているかを示す。Humanは、対象、知りたいこと、範囲、優先順位を訂正できる。

返答に特定の章や表を毎回要求する設計ではない。必要な結論、説明、根拠、条件、不明が読み取れることを重視する。

## 3. 一つの生活場面による説明用の仮例

以下は設計を説明するための架空の場面である。YusukeJPの実体験、新しいSkillを実行した結果、実生活で確認した効果ではない。

共通の設定は、出発前に鍵を探し、昨日の上着のポケットで見つかった場面とする。この人は日によって服やバッグを替えることがあると仮定する。ただし、鍵を探した当日に何を替えたか、どの時点で鍵を置いたかは未確認とする。

以下の文章は説明用の入力例であり、登録済みSkillの起動Queryではない。

### 3.1 経験を共有した場合

入力例：
「今日、出かける前に鍵を探した。昨日の上着のポケットにあった。」

新しい話題としてこの報告だけが届いた場合、AIは、出発前に探すことになり、昨日の上着で見つかった経験を受け取る。

この報告だけでは、探した時間、困り方、原因、改善を希望しているかは分からない。勝手に「注意力の問題」「収納の仕組みが悪い」と結論づけたり、収納用品の調査や新しい習慣の提案を始めたりしない。

受領と必要な文脈の整理で、今回の応答を完了できる。

一方、すでに「鍵を探すことになる流れを理解したい」という調査をしていたなら、同じ報告は「発見時の場所が確認できた」という更新になる。以前の仮説との関係を見て、必要なら次に確認する不足を絞る。

発言の文面だけではなく、継続中の目的が扱いを変える。

### 3.2 仕組みの理解を求めた場合

入力例：
「鍵が手元にない状態になる流れを整理したい。何と何のつながりを見れば分かる？」

AIは、鍵の位置、使った服やバッグ、持ち帰りと持ち出しの間の関係を、理解する対象として暫定的に切り出す。

仮例の報告から言えるのは、発見時には鍵が昨日の上着にあったことまでである。「帰宅時に移し忘れた」「今朝バッグを替えたために忘れた」という具体的な出来事は、まだ確認できていない。

調査するなら、まず現在の会話や既存の記録から、最後に鍵を使った場面、置いた場所、その後に持ち物を替えたかを、問いに必要な範囲で照合する。本人の現場に関する不足を、一般的な収納記事だけで埋めない。

説明では、例えば「鍵の場所が昨日の服に結びついたままだと、今日持っていく物とは一致しない場合がある」という関係を、条件付きの仕組みとして示せる。それが今回の実際の原因であるかは別に扱う。

今回の目的がその関係の理解なら、関係と限界が分かる説明を返して完了できる。必ず収納改善や行動試験へ進む必要はない。

### 3.3 方法の比較を求めた場合

入力例：
「鍵を玄関の決まった場所に置く方法と、その日に使うバッグの決まったポケットへ入れる方法を比べたい。服やバッグを替えても見つけやすくしたい。」

AIは、目的を「服やバッグが変わっても鍵の場所を捉えやすくすること」と受け取り、二つの方法が何に依存するかを比較する。

- 玄関の定位置：
  鍵の場所を、その日の服やバッグから独立させられる。
  帰宅時に戻し、出発時に取り出す流れと、適した置き場所が必要になる。
- その日のバッグの定位置：
  持ち出すバッグの中で場所を固定できる。
  バッグを替える時には、鍵を移す必要がある。

仮に、バッグを頻繁に替え、帰宅・出発の流れに合う玄関の置き場所が確保できるなら、玄関の定位置は「バッグ変更時の移し替え」に依存しない案として推奨候補になる。

反対に、いつも同じバッグを使い、外出先でもその中で管理したいなら、バッグ内の定位置を優先する理由がある。

この比較は、方法の条件と依存関係から導く設計上の説明である。どちらが実際に続けやすいか、鍵を探す回数が減るかは確認していない。

比較・推奨が求められた場合は、仕組みの説明だけで終えず、条件別の結論まで返す。比較依頼だけから、物の購入、配置変更、生活上の試行を実行する権限は生じない。

### 3.4 Correctionが入った場合

例えば、Humanが「バッグは毎日同じ。替えるのは上着だけ」と訂正したとする。

AIは、バッグを替える時の移し替えを重く見た比較を修正する。玄関の定位置を推した理由が弱まる可能性を扱い、同じバッグの定位置という案を再評価する。

訂正を受けても、単に説明中の語を直して以前の推奨を維持するのでは足りない。変わった条件に依存する判断まで更新する。

この訂正だけで、バッグの方法が本人に必ず合うことや、過去の鍵探しの原因が確定したことにはしない。

## 4. 対象が変わる時に、何を変えるか

共通するのは、対象と問いを捉え、根拠から関係を理解し、判断を変える不足を調べる方法である。使う根拠や調査方法は対象ごとに選ぶ。

- 道具の動きを理解する：
  説明書が示す標準の働きと、確認できる現物の状態・使用条件を照合する。説明書どおりに動くはずだという説明を、その現物の動作確認へ置き換えない。
- 仕事の流れを理解する：
  規定された手順と、実際の情報の受け渡し・判断・待ち時間を区別する。時間がかかった一件だけから、誰かの能力や態度を原因と決めない。
- コードの働きを理解する：
  実装、設定、環境、ログなどを用いて動作をたどる。コードを読んだことと、その環境で実行を確認したことを分ける。

人・行動・道具・情報・環境・時間を、毎回すべて調べる必要はない。対象を説明し、今回の問いへ答えるために必要な関係を選ぶ。
