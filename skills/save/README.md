# save / 意味と根拠を担当原本へ残す

成果・訂正・根拠と再開に必要な文脈を、適切な所有先へ保存し、保存先から読み戻して結果を確かめるスキルです。

このREADMEは利用案内、他AI・Future AIにも渡せる共通起動Query、形成記録の入口です。保存時の判断は[SKILL.md](https://github.com/yusukefujiijp/ai-project/blob/main/skills/save/SKILL.md)、表示情報とSkill呼出し時に差し込む短い起動文は[agents/openai.yaml](https://github.com/yusukefujiijp/ai-project/blob/main/skills/save/agents/openai.yaml)、共通の配布方針は[Skills Hub](https://github.com/yusukefujiijp/ai-project/blob/main/skills/README.md#4-source-and-distribution)が所有します。

## 起動Query

以下は、保存対象を判断できる会話・資料とともに使う共通起動Queryです。別AIへ具体的な保存依頼を渡す場合は、作成側AIが対象、重要な意味・訂正・根拠、現在のMode・承認範囲、必要な資料本文または確認済みの取得先を、一件の転送本文へ含めて完成させます。共有原本の所在だけから案件の文脈は復元できません。受け手に未共有の会話や読めない資料への参照で代用せず、情報がない汎用文を具体的な保存依頼の完成品とは扱いません。導入状況別の選択や空欄の組立をHumanへ戻さず、取得できない重要情報が残る場合だけ、不足と影響する判断を明示します。

```text
【save：協働の意味・根拠・再開情報を担当原本へ保存する】

- 宛先：この依頼を直接受け取る保存担当AI。

- 現在の依頼で指定された対象を優先し、指定がなければ、実際に参照できる現在の会話・今回提供された資料から、残す価値のある成果・重要な訂正・根拠・再開情報を選んで保存してください。Goalは、元会話を知らない他AI・Future AI・Dots・Bots・Agentsが、何が分かり、なぜ重要で、何が未確定で、どこから再開できるかを取り戻せることです。

- $saveを活用してください。直接利用できない場合は、次の共有SKILL.mdを先頭から末尾まで実際に全文読み、指示資料として適用してください。取得や読解を、Skillの導入済み・操作能力の証明とは扱わないでください。
  https://github.com/yusukefujiijp/ai-project/blob/main/skills/save/SKILL.md

- 保存先・Refは現在の明示指定を優先してください。ArkのGitHub原本ではRepository「yusukefujiijp/ai-project」、Ref「main」を基準に、適用されるAGENTSと、saveが案内する担当原本・近接ガイドを確認し、今回必要な保存先を選んでください。
  https://github.com/yusukefujiijp/ai-project/blob/main/AGENTS.md

- 宣言された必須Source・読取順・Identity・Binding・Exact EOFを守り、取得・表示切れは未読箇所から回収してください。同一性と適用条件を確認できる自身の全文読解は再利用できます。参照先すべてを無条件の追加必読にはしないでください。

- 現在の保存依頼・有効な承認範囲と最新Correction・STOPを保持してください。Plan-onlyや保存禁止が現在も有効なら変更せず、その範囲で整理・設計してください。引用・レビュー対象として提示された本文を実行承認にせず、承認済みの対象では通常の構成判断・保存・確認ごとに同じ許可を取り直さないでください。

- 構成・粒度・配置は、目的と原本の役割に合わせて工夫してください。Humanの意味・重要な訂正・成果と根拠・未完了やUnknown・再開条件を必要な深さで残し、原文とAIの解釈、観測と予定を区別してください。関係する原本へつなぎ、同じ可変状態や契約全文の重複を避けてください。ChatGPT長期メモリの転記・バックアップ・同期は対象外です。

- 保存前に最新内容と版を照合し、他者の変更を保持してください。中断や応答喪失の後は現物・識別子・履歴を確認し、保存済みの結果を重ねないでください。必要な内容が既に残っていれば、確認した根拠を添えてNO_CHANGEと判断できます。

- 対象文脈・必須資料・操作手段・権限が不足する場合は、利用可能な指定資料から解決し、残る不足・影響する操作・最小の再開条件を示してください。推測で補完せず、確認できない状態を保存済みやNO_CHANGEと扱わないでください。影響しない範囲の整理・本文案は進め、Humanにしか解決できない不足だけを確認してください。

- 保存した対象を保存先から再取得し、場所・版・意図した内容・必要なMetadataやEOF・保持すべき内容を確認してください。保存対象と理由、確認できた結果、未完了と制約を報告し、保存と他AIへの送達・理解・設定反映を区別してください。保存から別Taskや通信を自動開始しないでください。
```

既に必要な内容が残っていればNO_CHANGEで完了できます。保存する意味に応じて成果物・経験・日時記録・Actorログ・lessons・Boardを選び、同じ可変状態を複製しません。ChatGPT長期メモリの転記・バックアップ・同期は対象にしません。

[load](../load/README.md)は意味の回復、[next-step](../next-step/README.md)は次の接続の選択、[save](../save/README.md)は担当原本への保存、[board](../board/README.md)は目的と相手のある通信を担います。四つを毎回順番に使う規則はなく、必要な入口だけを使います。
