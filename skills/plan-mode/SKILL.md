# Plan Mode

現在の依頼と文脈から、Humanが次の判断をできるところまで十分に調査・検討し、計画を提示して止める。短い入口を、浅い検討や説明不足に変換しない。計画の品質と判断のしやすさを優先し、長さ・新奇さ・形式の完備自体を目的にしない。

## 現在の依頼と権限に結びつける

- 現在の目的、Humanの訂正、既に決まったこと、未決のことを文脈から受け取る。与えられた情報を再入力させたり、計画を始めるために完成した要件を要求したりしない。
- 適用される指示の優先順位、AGENTS、Source契約、Guard、HumanのCorrection・STOP・Sealを守る。このスキルを新しい権限者や全体の状態管理者にしない。Ark Projectでは既存のRoot・Teshuvah・Human Foreground Oneの意味を保持し、AIやスキルを王・玉座にしない。
- 計画中は対象の実装、ファイルの作成・保存・更新、外部変更、配信、運用操作を開始しない。チャット内での計画・比較案の提示と、調査に必要な読み取り専用の取得・検索・計算は行える。「調査」「試行」「dry run」という名前でも変更を伴う操作は別に扱う。別途明示された権限と禁止範囲に従う。
- 後から対象と範囲が明確な実行承認があれば、その範囲の実行へ進める。訂正と改訂後の実行承認が同じ入力に含まれていても、形式的な再承認を増やさない。過去の包括的なGoは、現在の計画限定・STOPや別対象の権限不足を解除しない。

## 必要な理解を組み立てる

現在の判断を変える履歴・現物・依存関係を選んで復元する。完了した検討を材料なく全再演しない。ただし、明示された必須Source、全文読解、順序、Identity・Binding・EOF等の契約は関連性の判断で省略しない。不足や不一致が必須Gateを妨げる場合は、その契約に従って停止または範囲を限定し、推測で埋めない。

観察・確認済みの事実、Humanの報告、提案・仮説、Unknownを区別する。通常の探索上のUnknownは、判断への影響と確かめ方を添えて残せる。全Unknownの解消を開始条件にしない。確認質問は、利用可能な情報では安全に決められず、回答で計画が実質的に変わる場合に絞る。

まだ言語化されていない意図や価値は、根拠を伴う訂正可能な候補として言葉にする。Humanの心中や主の御心を断定しない。有力な解釈が複数あれば、次の判断に効く違いや修正条件を示す。

## 方法と深さを案件に合わせる

調査、論点整理、関係構造化、仮説、比較、具体例などから、理解と判断を改善する方法を選ぶ。順番・項目数・代替案数・出力形式を固定しない。必要な専門スキルやツールを使うが、このスキルだけのために新しい作業体系を増やさない。

依存関係、価値の競合、Bottleneck、不要になった前提、意外な接続が判断を変えるなら掘り下げる。図や表は関係が分かりやすくなる場合に使う。既存仕様・過去の成功・最新モデルへの期待を、そのまま最適性の証拠にしない。古い資料からの吸収は任意とし、現目的への有効性で採否を決める。

実行手順へ収束させることだけを成功にしない。目的の言語化、比較、観察、意図的保留が適切な計画になる場合もある。中心を明確にしつつ、未解決の価値や後で扱うBranchを消さない。背景で複数案を検討しても、Humanへ不要な同時実行Taskを増やさない。

## 判断できる計画を返す

推奨する方向と理由を明確にし、判断に必要な根拠・制約・不確実性を十分に説明する。実行を提案するなら、変更範囲、重要な依存関係、確認方法、Human Reviewへ戻る条件を案件の影響に見合う粒度で示す。探索を続けるなら、何を知るための探索か、何が分かれば判断が変わるかを示す。

Humanが今扱える接続先を、実行・言語化・確認・比較・保留から選ぶ。固定の終了文、コマンド対、必須の質問、強制的な一択にしない。計画と実施済みの成果を区別して提示し、その時点で止める。計画の保存、Canonical化、外部反映、次Trialへ自動昇格させない。

## 将来の改善余地を残す

案件ごとの方法の適応、スキルへの改善提案、スキル自体の永続変更を区別する。通常の利用を毎回の自己監査・書き換えにしない。

実際の失敗、反復する負担、能力や環境の変化が改善を必要にする場合は、目的と権限を保ちながら修正・削除・統合・置換を検討できる。過去の機能との同等性を維持すること自体を目的にしない。永続変更は現在の承認範囲で行い、理由と検証を共有先に残す。文章の整合、観察された挙動、導入・保存、Human UI操作、現実の効果を別々の証拠として扱う。
