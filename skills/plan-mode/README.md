# Plan Mode / plan-mode

現在の依頼と未整理の意図を大局的に十分調査・言語化・比較し、Humanが判断できる計画と次の協働への接続を用意するスキルです。Plan-onlyでは通常のNext Queryまで提示します。必要な計画検証に伴う限定的な一時生成はSkillの条件内で扱い、対象の実装・成果物の永続保存・外部変更は始めません。短い入口からも必要な検討を担います。

## 起動Queryと使い方

今回の依頼とともに、次の一つの入口を使います。登録済みの環境と、共有本文を読む環境で共通に利用できるよう、原本への経路を含めています。

~~~text
【Plan Mode】

- 宛先：この依頼を受け取ったAI。

- $plan-modeを使い、現在の依頼と文脈を大局的に十分検討し、Humanの判断・閃きと次の協働につながる計画を提示してください。Plan-onlyとし、必要な計画検証はSkillの条件内で行い、Next Queryまで用意してください。対象の実装・成果物の永続保存・外部変更は行わないでください。

- Skillを直接利用できない場合は、共有原本を実際に全文読んで適用してください。
  https://github.com/yusukefujiijp/ai-project/blob/main/skills/plan-mode/SKILL.md

- 必須Source・読取順・Identity・Binding・Exact EOFを守り、同一性と適用文脈を確認できる読解は再利用してください。取得・表示切れは回収し、必須資料が不足する場合は、未確認範囲・影響・最小の回復方法を示してください。
~~~

検討品質、大局観、Feedbackによる見直し、Plan-onlyの停止位置、Next Queryへの接続は[SKILL.md](SKILL.md)が担います。Queryは今回の依頼を渡す入口です。今回固有の目的・背景・Correction・条件は、必要なだけ添えてください。短い入力を、浅い検討や説明不足の指示にはしません。

未整理の意図の言語化も対象とし、実装計画だけへ強制収束させません。現在の禁止・STOPを保持し、その後に明確な実行承認があれば承認範囲へ進みます。Next Queryの提示だけでは、その採用・実行・送信を意味しません。通常形式の例外や、次の依頼が不要な場合は、Skillが接続する共通契約に従います。

限定的な一時生成の適用関係は[共通の実行境界](../../AGENTS.md)、具体的な判断条件は[Skillの計画検証規定](SKILL.md#計画検証に伴う限定的な一時生成)に従います。条件内では必要な検証と自己生成物の後始末まで個別の追加承認なく進められますが、今回の依頼が生成やコマンド実行を禁止している場合は、その禁止を優先します。一時領域やGitの追跡外であることだけでは許容しません。資料取得のための読み取りと、外部状態を変更する検証を区別します。

上のQueryと[agents/openai.yaml](agents/openai.yaml)のdefault_promptは、YAMLとして読み取った値を一致させます。共通の詳細規則をQueryへ再掲せず、別の_queryファイル、旧Runtimeの巨大連結、追加の状態管理者は作りません。共有本文を読むこと、登録すること、実際の会話で使われることは別に確認します。
