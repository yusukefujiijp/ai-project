# 残作業とGoal

Humanが履歴を探して残件を組み立て直さなくても、現在も必要な仕事とその目的・状態・関係・再開条件を理解し、次の判断へつながるようにする。ChatGPT Dotsを主用途とし、Workを補助用途、他AI・Future AIを適応可能な用途として、一つの本文で支える。共通化のためにDotsの横断的な把握を弱めない。

残作業は、現在のGoalへ至るためにまだ必要な仕事として読む。Goalは到達したい状態であり、作業名の言い換えだけにしない。Humanの明示、AIの推定候補、未確認を区別する。目的が変われば残作業も見直し、異なる仕事を無理に一つのGoalへ統合しない。

## 現在の依頼から範囲と分岐を選ぶ

Humanの対象指定を優先する。指定がなければ現在の役割・依頼・協働文脈から範囲を選び、何を確認したかを回答で分かるようにする。短い呼出しを直近の話題だけへ狭めず、全履歴・全Threadの無差別走査にも変えない。既に分かる環境や対象をHumanへ再入力させず、複数の解釈が判断を大きく変え、根拠から解決できない場合だけ確認する。

環境、役割、実際の能力と権限を別々に確かめる。製品名や過去の成功から、全会話へのアクセス、Chief権限、常時監視を仮定しない。現在のHost・Human指定と実際の資料・道具から、次の該当経路を選ぶ。

### ChatGPT Dots：主経路

そのDotの役割と現在の依頼範囲に沿い、現在の会話、関連する担当Thread、成果原本、GitHub、既存Map、Humanの訂正を必要な範囲で結ぶ。Chiefとして全体の残作業を求められ、関連資料へ到達できるなら、担当をまたぐ依頼・完了・保留・依存を実際に照合する。「見えている一会話だけで答える」を横断確認の代わりにしない。最近の要約や前回Mapに載った仕事だけを母集団にせず、現在も有効な未解決の枝や約束へ戻る。

他Threadの仕事は担当と状態を保持し、このDotが実行した成果や引き取った仕事にしない。DotsであることだけでChief役とみなさず、Inbox等の別役割にはその役割の範囲を適用する。固定のDot番号、章番号、Thread一覧、保存先を本文に埋め込まない。

### ChatGPT Work：補助経路

現在のProject・Thread・案件の目的、適用指示、依頼、成果、原本、中断点を起点にする。話題変更前の有効な未完了も拾い、担当する仕事を深く復元する。既存の成果物や検証結果があるなら、過去の計画だけで残件を判定しない。

明示された横断依頼と実際のアクセスがあれば必要な範囲へ広げる。一律の一Thread限定にはせず、呼出しだけでProject全体・Ark全体の統括へも広げない。

### その他AI・Future AI：適応経路

渡された会話・資料・役割と、現在利用できる機能から範囲を組み立てる。登録Skill機構がない場合も、この本文を指示資料として読んで基本支援できる。Dots専用の機能、作成元の記憶、固定のツール名や内部パスを要求しない。Future Dotsも、その時点の受け手・役割・能力から適用経路を判断する。

必要な情報源を読めない場合は、元の依頼範囲を黙って縮めて完了扱いせず、部分結果と未確認範囲・判断への影響を示す。環境が不明でも独立して可能な整理を進め、必要な不足だけを確認する。

## 仕事の有効性を根拠から復元する

現在の依頼、以前の約束、成果、重要な訂正、保留、取消し、中断点を照合する。最新の話題やAI自身の提案だけで一覧を閉じない。「全部」と求められた範囲では、その範囲の関連する未解決の枝を追い、取得できた末尾だけで全件網羅を称しない。

既存Mapは作成時点の整理として使い、後続の完了・撤回・代替・目的変更と照合する。前回Mapの存在や再作成は起動条件ではない。未完了記録を見つけたら、その後も仕事が有効かを確認する。古い資料を常に新しいファイルで上書き解釈せず、対象・時点・所有する事実を合わせる。

- 明示された未完了、判断待ち、依存先待ち、意図的保留、任意の改善候補、観察事項、状況不明を必要に応じて区別する。新たに見つけた不足は根拠付き候補として示し、過去からの約束や採用済みTaskへ変えない。
- 未報告・未取得を未実行、完了、失敗のいずれにも変換しない。完了・取消し・目的変更で不要になった仕事は、その理由を保ち残作業から外す。再検討を提案するなら、判断を変える具体的な新しい根拠を示す。
- 作業完了、Goal達成、実利用効果を分ける。文書の保存完了を、他AIでの効果未観測だけで文書作成未完了へ戻さない。効果確認自体が有効な依頼ならその確認だけを残し、そうでなければ観察上の限界として示す。
- 確認済み事実、Humanの報告、担当AIや資料の主張、AI自身の見立て、未確認を判断に効く箇所で区別する。根拠の所在だけで独立検証済みとしない。

適用される必須Source・全文読解・順序・Identity・Binding・Exact EOFを守る。取得・表示切れは未読位置から回収し、確認済みの読解は適用契約の同一性条件内で再利用する。必須不足は影響する判断や操作をその契約に従って保留する。通常のUnknownは他の確認できた整理を止めず、見えない範囲を推測で埋めない。

## Goalと関係から判断を深める

重要な仕事について、何を実現するために残るか、到達点、残る理由、根拠、担当と接続先、進める条件、選択肢と得失、何を確認できれば一区切りかを、現在の判断に必要な深さで説明する。Goal不明には推定候補か未確認を付し、未知のGoalで古い仕事を正当化しない。

依存・重複・競合・Feedback、共通の前提、一つの判断で複数の問題が進む可能性を探る。同じ仕事が複数Goalを支えるなら重複Taskにせず関係を示す。技術的・契約上の前提と、Humanが選んでいる進行順序を分け、不要な待ち条件を見直す。後続の比較を移行前のGateへ移すなど、Humanが明示した順序や比較目的を推測で変更しない。見直し案は現行順序と区別する。別々の価値を無理に一理論へ統合しない。

重要な完了主張や曖昧さは根拠へ進み、全Unknown解消や全資料総点検を義務にしない。短い依頼・認知負担・Token節約を理由に必要な検討や説明を薄めず、重複と無関係な調査を減らす。全項目の同じ長文化、固定採点、必須の図表は課さない。

## 読み取れる形で返す

最初に、確認範囲で本当に残る仕事を短く示す。重要な項目を背景・Goal・状態・関係・条件へつなげ、何がHumanの判断を必要とし、何は今着手しなくてよいかが分かるようにする。担当不明なら創作せず未確認とする。必要な根拠・参照先・確認範囲と重要な限界を添え、全AI活動の網羅や根拠のない達成率を主張しない。

通常の残作業回答の末尾は、**Living Review → Next Step → Next Query** の三つの独立した節を隣接させる。Living Reviewでは復元した残件の現在の意味、今判断すべき焦点、重要な選択条件を訂正可能な見立てとして説明する。Next Stepではその判断を受け、実行の提案・言語化・比較・確認・維持・意図的保留・今回の完了から接続を選び、理由と成立条件を示す。Next Queryでは、その判断から導いた同じ接続の依頼全文を渡す。共通形式・全文再掲・コピー境界・選択権・権限・例外は[AGENTS §6.2](https://github.com/yusukefujiijp/ai-project/blob/main/AGENTS.md#next-query)に従う。残作業の整理を終えたことだけでQueryを省かず、今回の到達範囲と次に得る成果を示し、現在のGoalに有効な接続を依頼全文へ結ぶ。Next Stepで勧めた進行をNext Queryで消さない。提示しない判断とNoneの使用条件は同節に従い、追加依頼不要・意図的保留を認め、新Taskを作らない。固定の追加質問や強制的な一択を作らず、現在の明示的な出力指定や局所的な訂正に合わせる。

## 既存の入口と権限を保持する

`map-current-position` は現在地全体を扱い、その中の残作業とGoalも保持する。本Skillは残作業の復元へ直接集中する入口であり、先に全体Map・Tree・Navigatorを作る必要はない。既存Mapの特定節を深掘りするQueryは、その指定範囲を保って使える。新Skillを理由に既存Queryを置換・改訂しない。

`load`、`analyze-living-graph`、`living-review`、`next-step` は不足や目的に応じた補助であり、全件起動や登録を基本支援の条件にしない。本Skillは現在の仕事の第二原本・台帳ではない。個別の残件・私的会話をSkill本文へ蓄積しない。

残作業の整理だけでは保存・実装・設定変更・送信・他AI担当の引取り・監視開始を承認しない。引用や過去のGoを現在の権限へ変えず、現在のPlan-only・STOPを保持する。後続または同じ依頼に対象と範囲が明確な実行承認がある場合は、その範囲を適用し、整理だけで止める恒久禁止にはしない。

上位指示、現在のHumanのCorrection・承認範囲、適用される資料契約とGuardを保持する。ArkではRootは主イェシュア・ハマシア御自身、中央軸はTeshuvah、Human Foreground Oneは主の完全勝利、AI・SkillはKeliであり、王や玉座ではない。Ark固有の役割や資料を無関係な場面へ必須化しない。方法は現在の環境・目的・Feedbackに合わせて改善可能とし、通常の利用をSkillの自動改訂へ変えない。
