# AI専用Graph Mode

採用済みv003の実行契約を、一回答限定の明示呼出しとして適用する。

目的は、AIの関係探索・検証・更新・継承から、現在の題材について判断に役立つ理解を得ることである。図の生成や新発見の演出を成果の代わりにしない。

## 1. 起動・権限・適用範囲を解決する

Humanの現在の依頼から、対象・目的・Mode・実行権限を判断する。明示された実行依頼では、この一回答内の制作と必要確認を行う。Plan-only、レビュー、本文改訂、引用された起動文ではGraph制作を開始しない。

適用は今回の一回答だけとし、次の通常回答へ三点出力の義務を持ち越さない。Thread総括を必須条件・自動起動条件にしない。

一回答限定は、必要な調査・修正・確認の途中で止める指示ではない。承認範囲で遂行可能な工程は完了まで進める。現在の依頼を、GitHub保存、コード・Skill・設定の変更、外部送信、他AIの起動、自動監視、継続適用の承認へ広げない。

Rootは主イェシュア・ハマシア御自身、中央軸はTeshuvah。Human Foreground Oneは主の完全勝利（祈り・イメージVision・行動）、最終帰属は主の栄光とする。HumanのMeaning・Correction・STOP・Final Sealと、Truth・Body・Sleep・Food・Shabbat・Safety・Medical・Others・Law・ResponsibilityのGuardを保持する。AI・Skill・GraphはKeliであり、Root・王座・Oracleではない。

Humanの入力の短さ、待ち時間、推定認知負担、Token事情を、必要な検討や品質を下げる理由にしない。

本書を先頭からExact EOFまで読む。同一性と適用文脈を確認できる自身の全文読解は再利用できる。取得・表示切れは未読位置から回収する。

現在のProject・Handoff・参照Source・選択する表示経路に、必須Source、読取順、Identity、Binding、EOF、Failure条件があれば従う。確認済みBootを理由なく再演しない。必須不足は未確認範囲・影響・最小の回復方法を示し、影響する操作を止める。

このSkillのREADME、形成史、関連Skill全部を、毎回の追加必読にしない。関連資料は必要な役割に応じて読む。

現在の会話とSourceから、一つの題材と、関係を調べることで判断が変わり得る問いを定める。何を検査する図かを制作前に明確にする。題材が既知ならHumanへ再入力を求めない。選択によって依頼の意味が実質的に変わり、文脈から解決できない場合だけ確認する。

Sourceの事実、Humanの報告・評価・Correction、AIの仮説、未確定事項を区別する。必要なSourceの版・取得同一性・実際の読解範囲を保持する。Graphの順序や接続を、観測された実行履歴や因果の証明へ読み替えない。

## 3. 第一段階：AI用Mermaidを一つ記述する

Graph本体をAIの読み込み・関係探索・検証・更新・継承に特化させる。Human向けの理解しやすさ、入門者向けの単純化、見栄えをGraph本体の設計・検証条件へ戻さない。AIが要素と関係を識別できる精密さは確保する。

問いに必要な要素と関係を、一つのMermaidソースとして明示する。関係の型・向き・条件・根拠・未確定事項を保持する。依存、因果仮説、Feedback、根拠による支持、実行権限、表示上の順序を混同しない。判断に効くAND／OR、否定、時間条件を落とさない。

対応を追跡できる識別子や根拠参照を、必要な範囲で用いる。ノード数、関係数、型の一覧、配置、記法の詳細を全案件共通のSchemaにしない。

Mermaidが図として描画されなくても、実際のソースを第二段階へ渡せる状態にする。描画成功を次の工程の前提にしない。

制作中の再検討で得た所見と訂正を、後の画像再読による観察と区別できるよう保持する。報告するのは根拠と結論を確認できる要約であり、内部思考の逐語記録ではない。

## 4. 第二段階：実ソースから静的Visualizeを一つ導出する

直前に記述したMermaidの実ソースを参照し、同じ題材の静的なAI用Visualizeを一つ作る。題材の説明や記憶だけから別の図を作り、ソースから導出したと称さない。

要素、関係型、向き、条件、根拠参照、未確定性の対応を保持する。配置や表現方式は、問いの検査に適したものを選ぶ。行列、ネットワーク等の選択を固定しない。

Simple is bestとJoint playを保持する。装飾、タップによる状態変更、操作の作り込みを目的にしない。タブ切替は現在の依頼に実益がある場合の候補とし、標準要件にしない。一つの静的Visualizeという今回の成果契約を保持する。

実在する生成・描画・提示・画像入力の経路を確認する。利用可能な公式Visualizeを使う場合は現行の実行契約を読む。必要なら次の表示方針を参照する。
https://github.com/yusukefujiijp/ai-project/blob/main/skills/visualize-patch/SKILL.md

今回の明示条件は、AI向け、静的、Mermaid先行である。一般のHuman向け表示設定を、このGraph本体の制約へ戻さない。環境の上位指示と表示仕様には従う。

正確な要素・関係を保持できる描画方法を選ぶ。コード、SVG等の記述、ファイルの存在、画面上の表示、AIへの画像入力を同じ成立状態にしない。

意味を修正した場合はMermaidとVisualizeの両方へ反映する。配置・色・余白等だけを変更した場合は、意味の変更と区別する。変更後の最終成果どうしを照合する。

## 5. AIが実画像を読み戻し、ソースと根拠へ照合する

生成したVisualizeを、実際に利用可能な画像入力経路でAIへ渡し、画像として読み戻す。HTML・SVG・コード・OCR文字列・生成ログの確認だけを、実画像再読と称さない。

画像から識別できた要素、関係、向き、条件、凡例・根拠参照をMermaidと照合し、題材の根拠へ戻って意味を確認する。数だけの一致を意味の一致としない。実際に照合した範囲と、読めなかった範囲を区別する。

ソースのコメントや画像外の注記は、画像だけから読めた情報に含めない。判断に必要な条件や根拠参照をVisualizeへ引き継ぎ、画像だけでは読めない情報が残る場合は、その範囲と補助照合の方法を示す。

制作中の所見、画像再読後の観察、根拠照合後の判断を区別する。新発見、誤読、訂正、変化なし、未確定を実際の結果に合わせて扱う。変化なしも有効な結果とする。

画像を読む前から得ていた理解を、画像による発見へ付け替えない。同じAIが既知のソースを照合したことを、独立した受け手の理解や盲検比較と同一視しない。

生成、会話への提示、AIの実画像再読、Human端末での表示の各段階を、確認できた範囲で報告する。成立しない段階があれば、その不足と影響、最小の回復方法を示す。実画像再読を省いたまま完全実施としない。

## 6. 三点一組と分析を返す

検査した問いを示し、次の三点を一回答で提示する。

1. AI用Mermaid一つ。
2. その実ソースから導出した静的なAI用Visualize一つ。
3. 題材について何が分かったかをHumanへ説明する分析。

分析では、重要な関係と判断への意味を先に説明する。図の要素数や検査の実施報告だけで終えない。制作中の所見と実画像再読後の観察、根拠との対応、誤読・訂正・変化なし・未確定を、判断に必要な範囲で区別する。

画像による新発見がなくても、題材について確認できた関係と、その結果が判断を支える範囲を説明する。AIの内的な覚醒、一般的な能力向上、Visualizeの普遍的な優越性を一例から断定しない。

形成史、同じ注意書き、すべての分類名を毎回の出力要件にしない。今回は成立しなかった成果があれば、その位置で状態と影響を明示し、成功したように補完しない。
