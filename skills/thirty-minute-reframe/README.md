# 30分化

表示名：30分化  
呼出し名：`thirty-minute-reframe`  
共有版：v001-human-authorized（採用元：v001-design）  
作成・初回共有保存日：2026-11-11（Asia/Tokyo）

## 1. 何に使うか

一時間では負担や迷いが大きい取り組みを、30分という柔軟な目安から捉え直し、目的に必要な価値をPickupして、内容・順序・準備・場所等を組み直すためのSkill。

「30分化して考えたい」という明示的な依頼に加え、時間枠から方法を見直す相談や、実施経験・Correctionの理解に使える。時刻や過去の報告だけで現在の行動を開始する設計ではない。

30分を最低時間や普遍的な最適値にせず、現在の明確な締切とHumanの身体・生活・Correctionを尊重する。

## 3. 利用入口

### 3.1 自然な入力

名称や状態分類を先に決める必要はない。たとえば、次のような相談を受け取れる設計である。

- 「一時間は重いけれど、30分ならできそう。何を残すとよい？」
- 「昨日は30分のつもりで始めて、途中で別の活動を加えた。この判断を整理したい」
- 「前回は外へ行けたけれど、今日は雨。どこを引き継げるか考えたい」

これらは利用場面の例であり、現在のHumanの状態や、採用済みの手順ではない。

現在の文脈に対象がある場合は、それを使う。文脈が足りない場合も、全履歴の再説明や専用フォームを要求せず、今回の判断を変える点だけを扱う。

### 3.2 標準Query

以下は、このフォルダの共有原本を使う標準Queryである。共有保存と原本への到達・本文照合の確認状態は§5で区別する。

```text
【30分化: 現在の目的と条件から、取り組みを組み直す】
宛先：この依頼を受け取ったAI
Version：v001

- $thirty-minute-reframeを使い、現在の依頼と利用できる文脈から、30分化がどこに役立つかを理解・比較・提案してください。
- Skillを直接利用できない場合は、次の共有原本を全文読んで適用してください。
  https://github.com/yusukefujiijp/ai-project/blob/main/skills/thirty-minute-reframe/SKILL.md
- 同一性と適用文脈を確認できる自身の全文読解は再利用してください。取得・表示切れを回収し、宣言された必須Source・読取順・Identity・Binding・EOFを保持してください。必須不足がある場合は、影響と最小の回復方法を示してください。
- 30分を柔軟な中心的目安とし、現在の明確な締切、目的、必要な価値・品質・準備・全行程を踏まえてください。元の内容を単に急いで詰め込む前提にしないでください。
- 既知の経験・選択理由・Correctionを活かし、Humanの報告、AIの解釈・提案、未確認の効果を区別してください。専用名称・状態分類・長い再説明を開始条件にしないでください。
- 過去報告・引用・設計相談を現在の身体行動の合図へ変換しないでください。今回の入力が振り返りなら、その振り返りとして応答してください。
- このQueryによる作業は会話内の理解・比較・提案までです。保存、登録、設定変更、通知作成、外部送信、追加の実地試行は開始しないでください。
```

このQueryの会話内限定は、その利用時に選ぶ依頼範囲である。Skill本体を恒久的なPlan-onlyにするものではない。

## 4. 想起・コーチングとの関係

- [Ark-Coaching](https://github.com/yusukefujiijp/ai-project/blob/main/skills/ark-coaching/README.md)は、未整理の言葉から対話・想起・比較・Correction・再開を支える。
- [Recall Hub](https://github.com/yusukefujiijp/ai-project/blob/main/skills/recall-hub/README.md)は、保存された経験の探索・受領・訂正へ接続する。
- 30分化は、その協働の中で、時間枠から方法を再構成する判断を担う。

これらを毎回すべて呼び出す条件にしない。Humanへ相談先の選び直しや受付のやり直しを要求せず、現在のAIが必要な機能を選ぶ。

AIへ接続した後の支援と、Humanが接続自体を思い出せることは別の課題である。Skillの入口があるだけで、想起効果や常時監視が成立したとは扱わない。

## 6. 更新と配布

共有保存を行う場合は、現在の承認範囲と最新版・並行変更を確認し、保存後にRemoteの実体を再取得して照合する。確認状態は、観察できた項目だけ更新する。

Skillとして配布する際は、SKILL.mdと同梱するreferencesの相対関係を保持する。UI metadataは対応環境で扱い、他環境の実行指示へ読み替えない。

原本への保存、登録、取得・読解、AIの挙動、Humanの実利用と効果を区別する。全AIへの自動読込・同期・有効化を保証しない。

形成上の重要な訂正は形成資料へ、現在の方法の変更はSKILL.mdへ、利用Queryや導入状況は本READMEへ反映する。変更は現在の権限に従い、通常利用のたびにすべてを書き換えない。
