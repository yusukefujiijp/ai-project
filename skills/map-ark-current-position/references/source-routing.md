# 現在地を復元するための資料の辿り方

GitHub上の状態が今回の判断を変えるときに使う。これは資料の担当を探す案内であり、全件必読リストでも現行状態の写しでもない。Repositoryが変更されていれば、現在のHuman指定と現行の入口に従う。利用可能な正規のコネクタ・ツールを使い、接続や権限を仮定しない。

既知のRepositoryは `yusukefujiijp/ai-project`、既知の標準branchは `main`。別の対象が指定されていれば置換する。

| 確かめること | 入口の候補 | 担当範囲と注意 |
|---|---|---|
| 全体の規約・Domain案内 | `AGENTS.md`、ルート`README.md` | 権限と案内。すべての生活Taskの最新進捗ではない |
| 現在の章・Main・補助場 | `ark-project/README.md`と、そこから辿る現行Threadの入口・State | Threadを先に特定する。章番号をこのSkillから固定しない |
| GitHub整理・構造改善 | `control-center/PLAN.md`、`control-center/ARCHIVE.md`、`control-center/changes/`の該当記録 | 案件の到達点・検証・残点。Ark全体の万能Task一覧ではない |
| 生活との協働方針・開始支援 | `task-mode-system/README.md`、`task-mode-system/operation.md` | 方針・Correction。現在の身体状態や個別Taskの実行証明ではない |
| 経験と成功 | 現行Threadが指す経験原本、`success-cases/README.md`から必要な一件 | 当時の報告・評価・条件を読む。保存日と実施日、例と普遍性を分ける |
| chocoZAPの記録 | `chocozap/README.md`が指定する正本 | 前回・当日・訂正を実施日から解決する。数値だけで実施完了や効果を推定しない |
| Skillの共有・導入 | `skills/README.md`、対象Skill、利用環境の確認結果 | GitHub共有、利用環境への導入、他AIの理解を分ける。backup専用資料を共通の現用原本へ昇格させない |

1. まず今回の範囲を決め、必要な入口から当該内容の担当資料へ進む。指定HandoffのBootを行う依頼なら専用契約を優先し、この表で順序やRequired Sourcesを置き換えない。
2. 取得した資料の更新日・版・対象期間・役割を確認する。準備時点のStateと後続の案件記録が違う場合、どの事実をどちらが所有するか調べる。ファイルを勝手に修正して整合させない。
3. 「いま全体で何が進んでいるか」の判断に、別の作業の直近変更が影響し得るなら、関連する変更履歴も必要な範囲で確認する。Commit名だけで実装・利用・効果を認定せず、重要なものは差分や現行本文へ進む。毎回すべての履歴を再調査しない。
4. 確認できた枝・時点と、未確認の範囲を示して返す。資料側のRemote検証記録を読んだことを、今回自分が試験を再実行したという報告に変えない。古い資料が残る理由が不明ならUnknownとして扱い、削除候補の認定や新しい検証Taskを自動生成しない。

例えば、準備Stateに「未承認」、後続の案件記録に「承認・保存・確認済み」がある場合は、その案件の後続事実を反映し、Stateの準備時点を明示する。旧方式の試験が未実行でも、その採用目的が撤回されているなら、現在の必須Taskに戻さない。一方、互換性維持のため旧パスを残す移行では、「通常案内から退役」と「旧パスを削除」を分ける。
