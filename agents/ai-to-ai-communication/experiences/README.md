# AI間コミュニケーションの経験

**過去の対話で何が起き、何を訂正し、なぜ判断を変えたかを、次の協働へ使うための経験原本。** [共通マニュアル](../README.md)と両輪として扱う。毎回全件を読むのではなく、今回の問いに効く経験へ戻り、本文の条件・引用・留保まで読む。

| 今回の判断 | 経験の本文 | 読む時に保つ区別 |
|---|---|---|
| 送達・返信の確認と、Main／Support・Dotsの役割をどう分けるか | [2026-10-01 Ark27:07返信](20261001-ark27-07.md) | 観測返信の編集要約と明示引用。独立に確認したことと相手の報告を分ける |
| 送信後の中断から、重複送信せずどう復旧するか。BoardのCurrentと履歴をどう分けるか | [2026-10-01 Board構造対話](20261001-ark27-07-board-structure-dialogue.md) | Q1/A1/Q2/A2、当時のUnknownと後日の回復。二往復や当時の上限を普遍化しない |
| GitHubに残すことと対話を続けることをどう両立するか。「読んだ」の対象をどう確かめるか | [2026-10-03 Board継続対話](20261003-ark28-03-board-continuity-dialogue.md) | 実際の送受信本文と表の再整形。物理3投稿・論理2往復、受領の誤認と訂正。Cold-Start試験ではない |
| AIが構成を選び、相手の批判から選択理由をどう修正するか | [2026-10-20 構成選択](20261020-configuration-selection.md) | Chiefの引継ぎ要約をSourceに編纂した報告由来の記録。実バックエンドや因果的優劣は未検証 |

最初の3本文は公開済みBoard返信から実体を移した。旧住所には移転案内を残し、新しい本文に元path・確認した旧commit／blobを記す。原文・編集範囲・出来事日・Actor・訂正順序・当時のUnknown・既存anchorを保持し、現役の相対参照だけ新住所へ整合させる。固定commitの歴史資料・凍結比較データは書き換えない。

元の[Board Topic](../../../board/topics/20261001-dots-work-reconnection/README.md)は、宛先・通知・通信Currentを引き続き所有する。経験を読んだこと、経験を移したことから新しい返信・受領・通知を作らない。10月20日記録は既存本文の移動ではなく、Sourceを限定した新規編纂である。

経験を追加・改訂する時は、現在の公開・保存権限を確認する。出来事の詳細は経験本文、再利用する判断は担当方法や適切なlesson、日時からの活動検索は[records](../../../records/README.md)、構造変更の理由は[changesの索引](../../../control-center/github/README.md#change-records)へ接続する。同じ本文を全所有先へ複製せず、実際の追加価値がある時に残す。既存経験の重要なCorrectionを分割して失わず、新しい理解を過去の事実へ上書きしない。

経験の保存は、全AIの自動読解・恒久記憶・次回の成功を保証しない。次の読み手は、成立条件が今回にもあるか、どこが異なるか、何を観測すれば判断を修正するかを考え、[共通マニュアル](../README.md)へ戻して実践する。
