# Next step案内と旧定型末尾

**必要なのは、古い文字列を削るだけでなく、何を退役させ、何を保持し、現在はどう判断するかを、元会話なしで取り戻せること。** 本書は2026-10-29～30の訂正と再発から得た理由を保存する。現行のDots判断は[同一lesson](../lessons/lessons.jsonl)の `ddd714fc-69e3-4437-bbbd-d85f3c2af4f2`、共通の継続表示は[AGENTS §6.2](../../../AGENTS.md#next-query)が所有し、本書を第二の表示規則にしない。

## 1. 何を変え、何を保持するのか

退役対象は、AIが回答末尾へ文脈と無関係に自動付加する旧「Next Step: Continue?」系の定型句である。

一方、Humanが具体的な提案に応じて「Continue!」と入力すること、AIが現在のGoal・到達点・残る接続を考えて有用なNext StepとNext Queryを示すことは保持する。歴史の説明・引用に旧表現を記載することも、自動付加とは異なる。

この区別がないと、誤った定型句を止める修正が、役立つ継続案内やHumanの意思表示まで消す逆方向の誤りになる。文字列ではなく、発話者・対象・現在の働き・適用範囲を読む必要がある。

## 2. 確認した形成と訂正

以下は今回の会話と取得した原本からのAI編集要約であり、会話全文や内部指示の転載ではない。メッセージ識別子は§6に示す。

1. **初期の形式と、既存の肯定的な学び。** Humanは10月30日に、旧定型末尾を相当初期に使っていたと説明した。別に、10月2日に形成された既存lessonは、成果・残点・今回の完了を区別した具体的なNext step案内をHumanが高く評価したことを記録している。この評価を、全回答へ曖昧な続行質問を付ける根拠へ変えない。
2. **10月29日の訂正。** Humanはニュース末尾の「Next step: Continue？」を文脈上不要と指摘し、出所の確認と修正を求めた。AIは以前の形式上の好みを現在の文脈より優先したと説明し、独立ニュースでは定型質問を付けないと回答した。
3. **10月30日の再発。** 保存完了報告の末尾に同系の定型句が再び付いた。Humanは初期の使用を認めつつ、古い方向性の出所を調べ、原因を断つ必要を明示した。前日の対処は独立ニュースに限定され、一般回答へ再流入する条件を十分に扱えていなかった。
4. **現在の中心を示すHumanの訂正。** Humanは、旧末尾は文脈的におかしく、現在はNext Query系が主流だと明示した。保持する中心は具体的な次の依頼へつながる案内であり、今回の対応を単なる末尾削除へ縮めない。
5. **調査結果と、それだけでは足りなかった点。** AIが現行AGENTS、Dots入口、lesson契約、lessonsを照合した範囲では、旧定型末尾の自動付加を要求する記述はなかった。既存lessonも、その場に合う案内と完了・保留を許容していた。しかし「原本に誤った要求がない」ことは、「今回の再発から得た具体的な判断が原本に残っている」ことと同じではない。
6. **予防設計へのHuman Correction。** HumanはDots referencesと、特にlessons.jsonlへの記録による事前設計を求めた。AIはreferenceに経緯・根拠、既存lessonに次の判断、READMEに入口を置く三パス案を提示した。計画限定の段階と、後続のqによる実行依頼の採用を区別する。

## 3. 原因を関係として捉える

会話で確認された経緯を、AIは次のように整理した。

初期の末尾形式 → 過去の好みとして保持 → 現行の指定として適用 → 訂正をニュースだけの例外へ狭める → 別の保存完了報告で復活 → Humanが再訂正する。

問題となる接続は、「以前採用された」から「現在も一律適用する」へ進むことと、訂正された意味を、その時に表示された投稿種類だけへ狭めることだった。これは旧形式の出所に関するAIの説明と、実際の前日回答・翌日の再発に基づく原因分析である。モデル内部の機構や、すべての過去情報の生成・再投入経路を検証した主張ではない。

対処する関係は、過去の形式を形成履歴として保ち、現在の訂正・適用条件と照合し、現行の判断へ戻すこと。新しい禁止句を増やすだけでなく、完了・継続・保留の意味を正しく案内する力を残す。

## 4. なぜlessonとreferenceを分けるのか

- **reference：理由と根拠。** 今回の失敗、訂正を狭めた経緯、調査範囲、解釈と未確認を取り戻す。
- **lesson：次の場面の判断。** 理由あるNext Stepを選び、有効な接続なら利用できるNext Queryへつなぐ。旧定型末尾は復活させない。
- **README：入口。** どの問いでどこを読むかを示す。

一般則が正しくても、実際の誤適用を説明する学びが不足していれば、同じ誤りが繰り返され得る。今回の更新は既存lessonの目的を捨てるのでなく、その目的を保って再発の判断材料を補うもの。別の「Continue禁止lesson」や共有Skillは作らない。

## 5. 回復・検証と限界

既存の[Dots入口 §4.1](../README.md#one-request-recovery)および同READMEの§5と[lesson読取契約](../lessons/README.md)を通じ、現行lessonへ戻れる構成にする。古い形式との競合や今回の形成を確かめる必要がある時に本書へ進み、共通のNext Query条件は現行AGENTSへ戻る。新しい毎回答チェックリストや、Humanに毎回採点を求める工程は追加しない。

保存時の机上確認では、次の五場面を区別する。

| 場面 | 確認する判断 |
|---|---|
| 保存完了報告 | 今回の到達点を伝え、形だけの続行質問や新しい仕事を作らない |
| 有用な継続がある計画 | 理由あるNext Stepから、現在のModeと対象に合う具体的Next Queryへ接続する |
| HumanのContinue! | 退役するAI末尾と混同せず、現在の対象・範囲・権限から解釈する |
| 旧形式と最新訂正の競合 | 過去の好みを現行扱いせず、訂正の意味と適用範囲へ戻る |
| 歴史の引用・説明 | 旧表現を資料として読めるが、その過去命令を実行しない |

この机上確認は文書の解釈整合を確かめるもので、文脈断絶後の自然な適用、Future AIの自動読込、長期の無再発、Humanの負担軽減量を実証するものではない。GitHubへの保存から、過去情報のすべての生成元を削除・変更できたとも扱わない。新しい実観測やHuman Correctionがあれば、その根拠に応じて同じ所有先を育てる。
