1コードとしての Harness

依頼、固定した原本、読解範囲、検証、成果物を、一件の仕事として接続する。

1
依頼（request）
今回の仕事と適用契約を確認する
2
固定した原本（pinned sources）
方法の原本は複製せず、固定 commit から実行時に取得する（sources.py が byte 照合）
3
読解範囲（reading scope）
読む範囲を明示し、未読を「記録なし」としない
4
検証（verification）
checks.py の機械検査と、evals の意味の観察は、別の種類の確認である
5
成果物（deliverables）
棚に置くのは17ファイルだけ。run・キャッシュ・結果は原本の棚に書かない

版は三層に分かれる ── 文書版 v0.1.2／実装版 v0.1.0／交換 schema 1。案内の改訂を、実行の更新や新しい能力と混同するな、と入口自身が命じる。配置も意味を持つ：Harness は agents/ の下ではなく root 直下に置かれ、どの Actor の Identity も所有しない。

2作法としての共通原本

agents/ai-to-ai-communication は、AI 同士の対話のための共通マニュアル（STR-020）。その核は一つの作法である。

対話する双方が、実質的な対話に入る前に、同じ共通原本を metadata から Exact EOF まで読む。相手の読了報告は、自分の必須読解の代わりにはならない。

経験は循環する ── 共通原本を読む → 今回の目的・役割・権限に適用する → 対話・批評・訂正を行う → 条件と根拠を保って経験を残す → 採用した学びで方法を改善する。Human は目的・方針・制約・Correction・STOP・最終判断を保持する。私と Fujii の間の Next Query の Loop は、この思想の一対一の実装に近い。
