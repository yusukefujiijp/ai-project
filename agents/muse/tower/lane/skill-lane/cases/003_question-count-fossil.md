# Case 003 ── 問いの数の化石化の修繕

Case 002 の follow-up として封印された「引用の棚卸しの再走査」から生まれた案件。走査そのものが検出器になった ── 探していたのは残りの複製であり、見つかったのは、所有者自身の見出しに残った古い数だった。

## 1. 検出（再走査の結果）

Case 002 の実行後、agents/muse の canon（根文書と各家の README・憲章）を対象に、版の固定・数の複製・旧名の引用を再走査した。

- **健全だったもの（事実）** ── yomiyasu の規範文の固定は残っていない（他の「2.5.0」は全て日付のある記録）。CONTROL §3 が引く DESIGN-LAW v003 は、ファイル自身の版と一致する。「レポート」の残りの用例は全て過去形の歴史の記録であり、時制の物差しにより保持が正しい。
- **初めて実数で確かめたもの（事実）** ── 三本柱の件数を jsonl の実レコード数で数えた ── feedback 32／lessons 21／success-cases 22、全件 JSON として妥当。CONTROL §3 の「32／21／22」は、2026-11-07 以来未検証だった主張だが、真実だった。
- **見つかったもの** ── 問いの数に関する2件。いずれも Case 002 の欠陥4a（GOAL §7 の「8つの問い」）と同じ家族である。
- **範囲外（未確認）** ── Report 本文（001〜011）と herd-cards の judgment-tasks の内部の引用は、この走査に入れていない。

## 2. 再検証

1. **候補1 ── README §3 の見出し** ── agents/muse/README.md（当時 v013）の §3 の見出しが「## 3. 復元検証（8つの問い）」のままだった。同節の問いは、1〜8 に v005 追加の 9・10 と v010 追加の 11 を加えた 11問である。見出しは、所有者自身のファイルの、いちばん目立つ場所にある。解釈 ── 見出しは本来の8問のテストの固有名として読むこともできるが、復元者が最初に会うのはこの見出しであり、総数として読まれるのが自然である。なお §3 の導入文は既に数を持たない形（「次の問いに全て答えられたら」）であり、遅れていたのは見出しだけだった。
2. **候補2 ── report README の読み順** ── artifacts/report/README.md（当時 v016）の憲章の読み順が、根 README の §3 を「§3 検証（第11問まで）」と引いていた。今日は正確だが、所有者の外への数の複製であり、12問目が増えた日に静かに嘘になる形だった。

## 3. 設計と判断

- **候補1** ── 甲案「11の問い」と数に直す案に対し、乙案 ── 見出しから数を外し「## 3. 復元検証」とする ── を推奨し、採用した。問いの数は §3 の本文だけが所有する。README §4 の過去の条にある「8問検証は変更なしで有効」の反復は、当時の記録として保持する（時制の物差し）。
- **候補2** ── 「§3 検証（問いの全て）」のポインタ形へ改める。候補1と同じ家族であり、判断事項として「一緒に直す」を推奨し、同じ束で実行した ── 「いま正しいから」と残せば、次の化石化の種を1つ残すことになるためである。

## 4. 実行（YusukeJP の封印を受けて）

- 全ファイルを1回の push に集約した（仕様003 ── 1束1認識）。本書は、その push に含まれる。
- README v013 → v014（候補1 ── §3 の見出しの無数化と、版履歴への記録）
- artifacts/report/README v016 → v017（候補2 ── 憲章の読み順のポインタ化）
- 家の記録 ── 本書（cases/003）の新設、家の README v002 → v003（cases の一覧と憲章5「現在地」への追記）、cases/README v002 → v003（一覧への 003 の追加）
- あわせて、この案件の前段として、CONTROL §3 の Skill LANE 行の現在地の現行化（CONTROL v020）が、同じ日の先行する束で実行済みである。

## 5. 検証

- 読戻し検証 ── push の後に全ファイルを読み戻し、blob SHA が手元の原稿と一致することを確認した。
- grep による確認 ── README §3 の見出しに数が無いこと／report README に「第11問まで」が無いこと／版履歴の歴史的表記（「8問検証」等）が保持されていること。

## 6. 学び（一般化）

1. 棚卸しは、直した場所の外だけでなく、所有者自身の「顔」（見出し・表題）まで届いて初めて完了する。数は、本文の奥より先に、見出しで化石化する。
2. 「いま正しい複製」は、欠陥の予備軍である ── 正しさは今日の性質であり、複製は明日の嘘の構造である。直すかどうかは、今日の正しさではなく、変わり続けるものかどうかで判断する。
3. 走査の副産物として、未検証のまま引用されてきた数（32／21／22）を実数で確かめることができた。棚卸しは、欠陥を探す作業であると同時に、主張を事実へ格上げする作業でもある。
