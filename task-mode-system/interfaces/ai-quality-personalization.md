# AI回答品質とChatGPT設定への接続

## 1. この入口の役割

Humanは、AI品質の長期原則を他AI・Future AIへ継承できるように、ChatGPT全体の指示とプロフィールを整えることを求めた。今回の正確な貼付本文と版は、次の二つが所有する。本書へ同じ本文を複製しない。

- [Global Custom Instructions（GCI: ChatGPT全体カスタム指示）](../../_system/chatgpt/global-custom-instructions.md)：5000文字以内の全体協働方針、重要なCorrection、採用理由、設定間の境界。
- [User Profile](../../_system/chatgpt/user-profile.md)：現在提示された1500文字以内のプロフィールを、改稿せず保持した原本。
- [Ark27 Project指示](../../ark-project/ark27/INSTRUCTIONS.md)：Ark27固有の表示・運用・Source契約。全体設定とは別の適用先。

品質原則の成立理由は[現場運用 §4.2–4.3](../operation.md)、当時の直接の依頼・訂正は[05経験原本](../../ark-project/ark27/ark27-05/task-records.json)の `quality-correction`・`durable-quality-principle`・`memory-profile-request` にある。これらはHumanの発言と経験の記録であり、ChatGPTアカウントメモリの取得結果ではない。過去の依頼を現在の実行権限へ変えない。

## 2. 品質原則を取り違えない

Humanの開始改善・簡潔なI/O・B-Gateと、AIが十分に検討・調査・判断・言語化することを両立させる。Humanの待ち時間や推定認知負担を理由に、AI品質を独断で下げる方向へ戻さない。「長文が好き」「行動優先」とだけ要約すると、この区別が失われる。

方法・構成・創発性は開く。長さを固定せず、現在のHuman Correction・STOP・明示形式と適用Guardを保持する。詳細な協働方針はGCI、Ark固有の運用はProject指示を読む。

## 3. メモリをGitHub化しない

Humanは、GCIとプロフィールのGitHub保存を求める一方、ChatGPT長期メモリの内容はGitHub化しないと明示した。メモリの転記・バックアップ・同期・取得結果の保存は行わず、メモリ用の第二の正本を作らない。

旧0.1.0のメモリ転送文は、アカウントから読み出した記憶ではなく、当時の依頼に基づく入力案だった。今回の境界に合わせ、現行の貼付導線から除外した。Git履歴の書換えや、アカウントメモリの削除・編集はこの改訂に含まれない。直接のHuman発言からGCIの品質原則を整備することと、メモリ内容の輸出を混同しない。

## 4. 反映と確認

設定へ反映する場合は、目的の欄と対象本文を確認し、各所有資料の貼付ブロックだけを使う。旧品質原則の差込文を、完成したGCIへ重ねて追加しない。プロフィールとGCIを同じ欄へまとめない。Project指示が全体指示を上書きする範囲では、意味の整合を確認する。

GitHub保存、保存先からの再取得、Humanの設定操作、アカウントからの直接再読、独立した他AIの理解、実生活での効果は別の到達点である。今回の文書改訂はアカウントの設定操作や次Trialを実行するものではない。既に確認済みの入力上限を理由なく再調査しない。

Rootは主イェシュア・ハマシア御自身、中央軸はTeshuvah、Human Foreground Oneは主の完全勝利（祈り・イメージVision・行動）。AI・設定・文書はKeliであり、HumanのCorrection・STOP・Final Sealと適用Guardを保持する。
