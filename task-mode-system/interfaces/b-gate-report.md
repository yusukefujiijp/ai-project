# B-Gate報告

## 1. 目的と身分

「Query組立困難: B-Gate検出状態」を送る際、説明を一から組み立てる負担を減らすための項目と候補である。Humanが重要としたのは、状態が来てから詳細Queryを考えることを前提にせず、入力・選択できる入口を事前に用意することだった。

本版はArk27:03の対話と承認済み計画を文書へ具体化したPrototypeである。名称の採用・User辞書登録報告は[02原本](../../ark-project/ark27/ark27-02/task-records.json)の`adopted-name`／`s20`、項目設計と訂正は[03原本](../../ark-project/ark27/ark27-03/task-records.json)を参照する。全項目の実用性が実地で確認された意味ではない。

**埋められる項目だけでよい。名称だけ、一項目だけ、自由文だけでも報告として受け取れる。** 日付と時刻を含め、全欄入力を送信条件にしない。候補は自由に置き換えられる。

```text
✍️【B-Gate報告】
Query組立困難: B-Gate検出状態

日付:
時刻:
〔必要なら: 今／○時頃／○時から〕
場所:
〔候補: 自宅／職場／移動中／chocoZAP／その他〕
今していること:
〔候補: 起床後／AIとの対話／X・SNS・動画閲覧／家事／食事／仕事／移動／Workout／休憩／就寝準備／その他〕
進み具合:
〔候補: 始める前／途中／一部終了／全て終了／中断中／不明／該当なし〕
頭の状態:
〔候補: 文章が組み立てにくい／考えがまとまらない／決められない／何をするつもりだったか分からない／説明しにくい／不明〕
身体の状態:
〔候補: 特に気になることなし／眠い／疲れている／空腹／喉が渇いた／痛み・不調あり／説明しにくい／不明〕
今できそうなこと:
〔候補: 短文を読む／選択肢を選ぶ／一言返す／簡単な動作／休む／返信も難しい／分からない〕
時間・予定の制約:
〔候補: 特になし／出勤・外出が迫っている／就寝したい／約束・用事がある／その他〕
〔必要なら: ○時まで／あと○分〕
AIへの希望:
〔候補: 次の一手を一つ示して／選択肢で聞いて／一緒に状況を整理して／短く声をかけて／今は報告だけ／分からない〕
補足・BrainDump:
```

## 3. 項目をどう使うか

場所・今していること・進み具合は、場面とTaskの段階を伝える。頭の状態・身体の状態・今できそうなことは、認知的な困難、身体の報告、現時点で可能そうな応答を伝える。これらを一つの「重症度」へ変換しない。

「全て終了」は、何の範囲が終了したかに依存する。chocoZAPのメインだけか、アフターを含む全てかで接続が違う。「簡単な動作ができそう」は実行の約束でも、全Guardの確認でもない。

「AIへの希望」は支援の向きを示す。「今は報告だけ」なら、明示された急を要する事情等がない限り新しいTaskを追加しない。候補に「不明」がなくても、その欄で不明と書いてよい。

## 4. 省略と選択

以下は同じフォームの省略例であり、新しい採用名称や別の必須Templateではない。説明用の架空例で、Humanの実行報告ではない。

```text
Query組立困難: B-Gate検出状態
場所: 自宅
今できそうなこと: 選択肢を選ぶ
AIへの希望: 選択肢で聞いて
```

同じ入力から、AIは既知の文脈と組み合わせて不足を一つずつ扱える。日付・時刻・残り全項目を一括で追加質問しない。AIが候補に番号を付ける場合、その番号の意味を同じ応答で示す。端末に実在しないボタンを「押せる」と案内しない。

辞書やコピー機能への登録は、使う端末とHumanの選択による別操作である。送信できない場合、会話AIは無報告からB-Gateの発生を検出できない。本資料はバックグラウンド監視・自動通知を実装しない。

## 5. Feedbackの見方

実際の機会があれば、合図を呼び出せたか、どの欄なら使えたか、AIが余計な説明を要求しなかったか、何へ接続したかを、得られた報告の範囲で学ぶ。全部の測定や試験をHumanへ課さない。

命名、辞書登録報告、送信、選択の容易さ、行動、実生活の効果を分ける。良い評価だけから全段階成功へ進めない。フォームへのCorrectionは[改訂ガイド](../maintenance.md)に従い、理由を残して更新する。
