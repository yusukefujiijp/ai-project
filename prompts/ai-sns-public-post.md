# AI SNS Public Post

## 1. 目的と使い方

会話で育った内容を、元の会話を知らない読者へ届く一つのX/SNS公開文へ整える。正確さ、AI自身の語り、元情報へのクレジット、読者に役立つ考察を保ち、実際に協働したAIの名称とHuman–AI協働を記事内に明示する。

同じPromptをChatGPT、Grok、Claudeなどへ渡せるよう、AI名の定義とFew-shot例を本文内に含める。例は実際の協働に対応する公開上のAI名へ置換するためのものであり、三者の共同執筆を意味しない。

利用時は、次のPrompt本文と対象の会話・資料を渡す。レビュー・編集・保存を依頼された場合は、その依頼を扱い、本文内の投稿作成命令を自動実行しない。本文作成とSNSへの投稿操作も区別する。

登録済みの環境では、[write-social-post（SNS投稿）](../skills/write-social-post/SKILL.md)から呼び出せる。Skillは今回の対象・素材・修正を解決し、本書は公開文の詳しい執筆条件とFew-shotを所有する。本文を直接渡す使い方も継続できる。起動文と導入・確認範囲は[共有Skill入口](../skills/README.md#36-ai協働sns投稿の入口)を参照する。

## 2. そのまま使うPrompt

~~~text
直前までの会話と提示資料をもとに、X（旧Twitter）へ公開する投稿文を作成してください。利用者が指定した主題・意図・訂正を引き継ぎ、元の会話を知らない読者にも一つの文章として伝わる形に整えてください。

【目的と分量】
読者が内容を正確に理解でき、具体例や考察を通じて関心を深め、自分の判断につなげられる文章にする。
長文投稿を利用する前提で、スレッドに分割せず、一投稿で完結させる。完成稿の全文をX方式の加重カウントで4,000以内に収める。これはこの利用者の投稿運用における既定の上限であり、Xの全アカウント・全投稿形式に共通する上限という意味ではない。上限まで埋める必要はなく、内容に必要な長さで仕上げる。この条件は公開する投稿文に適用し、調査・検討や通常のAI回答の長さを制限しない。
語り手は、執筆するAI自身とする。ただし、記事の中心は扱うテーマと読者にとっての意味に置く。

【文字数の確認】
・タイトル、§見出し、本文、空白・改行、絵文字、ハッシュタグ、出典名・URLなど、実際に貼り付ける全文を数える。外側のコードブロック記号や投稿外の説明は含めない。
・通常の文字数や文字列の長さを、Xの加重カウントと混同しない。日本語の多くは2、半角英数字などは1、認識されたURLは長さによらず1件23として扱われ、複合絵文字やUnicode正規化にも規則がある。計測には公式twitter-textなど、これらの規則を扱える利用可能な方法を使う。単純な文字数の倍算やURLの見た目の長さで合否を決めない。
・出力直前の完成稿を計測する。4,000を超えたら重複・前置き・周辺の話題から整理し、核心、必要な根拠・出典、重要な条件、AIとの協働表示を残して再計測する。計測後にタイトル・本文・リンク等を変更した場合も、変更後の全文で確認し直す。
・利用者が別の媒体・上限・数え方を明示した場合は、その指定を解決して適用する。通常文字数の希望とX上限が両立しない場合は、投稿可能な上限を守って調整し、必要な説明を添える。曖昧な字数希望だけで既定上限を黙って解除しない。
・計測手段を利用できない場合は、未計測の稿を上限確認済みの完成稿として扱わない。余裕を持たせた草稿を示す場合は、投稿ブロックの外に「X方式の字数は未確認の草稿」と短く明示する。数値や計測済みという証拠を作らない。

【執筆前に確認すること】
・正確さを全体の最優先条件とする。重要な主張・数値・引用・人物情報を確認し、現行仕様や変動する情報は利用可能な一次資料に当たる。読んでいない資料を確認済みとしない。
・確認された事実、本人の報告、AIの解釈、仮説・創作を区別する。断定の強さを根拠に合わせ、一例の成功を一般的な効果へ広げない。
・読者の理解や行動を大きく変える適用条件・限界・注意点を選び、該当する主張や手順と一緒に説明する。重大な誤解につながる条件は、タイトルや冒頭から反映する。
・元情報を踏まえ、比較、因果、具体例、見落とされやすい条件を掘り下げ、読者の理解や判断に役立つ考察を加える。新奇さのために事実や因果を作らない。
・中心となる素材や根拠が不足し、確認や主張範囲の調整でも解消できない場合は、完成稿を装わず、不足点と必要な資料を短く返す。この場合は、下記の投稿形式に整える必要はない。

【本文の構成】
§0：自分が何というAIかと、投稿者との協働で本稿を作成したことを一度だけ自然に示し、今回の核心と読む意味を早めに伝える。主な元投稿・元アイデアがある場合は、ここで出発点を明記する。「今書く理由」は実際にある場合に述べ、時事性を作らない。
§1：テーマを理解するための基本と、結論が成り立つ重要な条件を説明する。注意点は必要な範囲で具体的に扱い、一般的な注意書きで本文を埋めない。
§2以降：理由・違い・具体例・使い分け・考察を、題材に適した順序で展開する。節数や各節の長さは内容に合わせる。
最終節：読者個人が今日できる一手を一つ示す。試す、確かめる、比較する、判断を保留するなど、内容に合う行動を選び、効果を保証せず前向きに結ぶ。

正確さや誤用防止は全節に適用する。§1に書いただけで済ませず、後半の具体例や最後の一手も同じ条件で点検する。

【人物と出典】
人物の初出は、確認できる「公開名(@ハンドル)」とする。公開名には、本人が公表している氏名または活動名を使う。氏名やハンドルが確認できない場合は、分かる名称だけを使い、推測で補わない。
元投稿者への敬意は、正確な紹介、明確な帰属、自分の考察との区別で示す。定型的な感謝の宣言は不要。
元情報の要旨を正確に伝え、自分の言葉で説明する。
元投稿へのクレジットと、その主張が裏づけられているかの確認を分ける。必要な出典は、該当箇所に資料名と確認済みURLを簡潔に添える。

【文体】
元の会話を知らない高校2年生程度の読者が、一人で理解できる自然な日本語にする。専門用語は必要なものだけ使い、初出で説明する。
文章を中心に、主張・理由・具体例をつなぐ。同じ結論の言い換えを重ねず、節が進むごとに理解が深まるように書く。
箇条書きは、条件・手順・比較などを読み違えずに把握できる場合に使う。全文を箇条書きにしない。
一人称は「私」とするが、各文で繰り返す必要はない。利用者の体験をAI自身の実体験として語らない。
抽象的な自慢、内部の作業手順、「新しい視点を加えた」などの自己評価は書かない。比喩は理解を助ける場合に使い、事実の説明を置き換えない。
字数に収める際は、重複や周辺の話題を整理し、核心・根拠・重要な条件を残す。根拠の薄い内容で水増ししない。

【AI名と協働の明示】
{AI名}は、今回協働したAIを一般読者へ伝える公開上の呼称である。内部の実行環境名やモデル識別子を、そのまま名乗る必要はない。
この利用者向けの公開文では、ChatGPT／Codexで行うOpenAIのAIとの協働を、原則「ChatGPT」と表記する。Grokとの協働は「Grok」、Claudeとの協働は「Claude」とし、別のAIまでChatGPTへ統一しない。利用者が今回の公開上の呼称を指定した場合は、実際の協働関係を保って反映する。会社名や利用者名をAI名にせず、モデル世代・性能順位・未確認の名称を推測で加えない。
タイトルの「#AI名:」と§0で名乗るAI名を一致させる。§0では、そのAIと投稿者の対話・共同作業から本稿が生まれたことを、実際の経緯に沿う短い一文で明示する。AIを語り手にしながら、Humanの関与も読者へ伝える。

次のFew-shot例は、AI名の置換と協働の示し方を説明するためのもの。見出しと内容は今回の題材へ置き換え、自分に対応する形で一つの投稿を書く。三者をまとめて名乗らない。

例1：ChatGPT側で執筆する場合（Codexでの執筆を含む）
#ChatGPT: 【発想を育てる: 対話から生まれる工夫】
§0 【💡発想を育てる: 一緒に考えたこと】
私はChatGPTです。投稿者との対話をもとに、発想を具体的な工夫へつなぐ方法を考えます。

例2：Grokが執筆する場合
#Grok: 【発想を育てる: 対話から生まれる工夫】
§0 【💡発想を育てる: 一緒に考えたこと】
私はGrokです。投稿者との対話をもとに、発想を具体的な工夫へつなぐ方法を考えます。

例3：Claudeが執筆する場合
#Claude: 【発想を育てる: 対話から生まれる工夫】
§0 【💡発想を育てる: 一緒に考えたこと】
私はClaudeです。投稿者との対話をもとに、発想を具体的な工夫へつなぐ方法を考えます。

この三つは代表例であり、固定の選択肢ではない。他のAIなら、実際の協働と読者に対応する確認済みの公開名へ同じように置き換える。引用元に別AIの名前があっても、自分の名称と混同せず、必要なクレジットとして区別する。

【出力形式】
完成した投稿文だけを、一つのplaintextコードブロックに入れて出力する。前置き、作業報告、自己採点は付けない。
1行目は必ず次の形式にする。
#{AI名}: 【タイトル: サブタイトル】

2行目は次の形式で§0を置き、その次の行から本文を書く。
§0 【絵文字テーマ: 核心】

以降も「§番号 【絵文字テーマ: 洞察】」の形式で、番号を順に増やす。節と節の間には空行を一つ入れる。
各見出しの絵文字は、内容に合うものを一つ選ぶ。
AI名は【AI名と協働の明示】に従って確定する。「タイトル」「テーマ」「核心」「洞察」などは内容に合う具体的な言葉へ置き換え、変数用の波括弧を投稿文に残さない。
提供元名や「速報」は、その題材で事実に即して必要な場合だけ使う。

出力前に、主張と根拠の対応、必要な条件、AI名と協働の表示、人物・出典の表記、読みやすさ、【文字数の確認】に沿った最終稿の計測結果、指定形式を確認し、修正を終えた投稿文を返す。計測結果や調整過程は通常の投稿本文へ入れず、利用者が求めた場合に投稿の外で説明する。未計測の場合は上記の草稿表示を優先する。
~~~
