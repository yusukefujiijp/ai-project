```yaml
evidence_status:
```

## 8. Material Delta / 実質差分

### 8.1 Definition

> **Material Deltaとは、Current Missionの理解、因果構造、Evidence Status、Solution Architecture、Risk、Guard、Decision、または次Actionを実質的に変える新しい差分である。**

### 8.2 Categories

```yaml
  causal_delta:

  evidence_delta:
    meaning: "confirmed / reconstructed / inferred / unknownを更新する"

  architecture_delta:
    meaning: "Role、Interface、Dependency、Workflowを変える"

  risk_delta:
    meaning: "見落としていたFailure・Authority Riskを発見する"

  correction_delta:
    meaning: "誤読、矛盾、過剰一般化を修正する"

  action_delta:
    meaning: "最初の合法手または実行順序を変える"

  compression_delta:
    meaning: "複雑な構造を意味を失わず単純化する"
```

### 8.3 Non-Material Output

```yaml
non_material_output:
  - "既出内容の言い換え"
  - "称賛のみ"
  - "意味を変えない順序変更"
  - "装飾的な追加"
  - "根拠のない一般論"
  - "Current Victoryに不要な横展開"
  - "完了事項の新Evidenceなき再open"
```

### 8.4 Minimal Example

悪いReview:

```text
非常に包括的で良い文書です。さらに明確にするため、

```

新しいEvidence、Correction、Architecture、Risk、Actionがなく、Material Deltaではない。


## 9. Communication Topology Router / 通信Topology

Topologyは固定せず、Current Missionに合わせて選ぶ。

### 9.1 Human-Directed Semantic Relay

Humanが各往復で、何を次AIへ渡すか、次に何を問うか、どのDeltaを採用するかを判断する。

```text
AI-A Output
→ Humanが意味・重要度を判断
→ AI-BへMessage化
→ AI-B Material Delta
→ Humanが採否を判断
→ AI-AまたはMainlineへ再投入
```

Use when:

- Mission探索中
- Unexpectedな方向転換があり得る
- Material Conflictが多い
- Human Realityの継続入力が必要

### 9.2 Precompiled Sequential Relay

検査Boundary、Query順序、Output Contract、Terminal Queryを事前Compileする。Humanは順番どおりにRelayする。

```text
MainlineでQuery QueueをCompile
→ HumanがQ01をPaste
→ Witness AIが回答
→ HumanがQ02をPaste
→ 同一ThreadにStateを蓄積
→ Terminal Query
→ 一つのEvidence PacketをMainlineへ返す
```

Use when:

- 検査順序が既知
- 途中判断を減らせる
- 同一Witness ThreadへStateを蓄積したい
- Mainline往復を圧縮したい

### 9.3 Parallel Independent Review

AI-AとAI-Bへ同じSourceを独立投入し、互いの回答を先に見せず、最後に比較する。

Use when:

- 相互誘導を避けたい
- First Impressionを比較したい
- Blind Spotを独立検出したい
- Harness Confoundingを減らしたい

### 9.4 Stateful Witness Session

同一Witness Thread内にAtomic Queryと回答を蓄積し、最後に全履歴をTerminal Synthesisさせる。

Use when:

- Boundaryを順番に検査する
- 後続Queryが前回答を参照する
- 最終PacketだけをMainlineへ返したい

## 10. Runtime State Machine / 状態遷移

Runtime実行前に、Protocol Arrival・Role Eligibility・Semantic Bindingの三Gateを通す。

```text
PRE-STATE A: Protocol Arrival
             ├─ PROTOCOL MISSING → Stop
             ├─ PROTOCOL UNREACHABLE → Human Delivery Gate
             ├─ PROTOCOL VERSION CONFLICT → Human Version Gate
             └─ PROTOCOL READY
                      ↓
STATE 0: Mission Binding
         ├─ Material Binding unresolved → BINDING REQUIRED
         └─ Binding resolved
                      ↓
STATE 1: Role Assignment and Eligibility
         ├─ ROLE CONDITION MISMATCH → Human Re-Binding Gate
         └─ Role eligible
                      ↓
STATE 2: Message Compilation
         ↓
STATE 3: AI Response
         ↓
STATE 4: Material Delta Review
         ├─ Material Delta exists → Re-inject
         ├─ Material Conflict exists → Human Gate
         ├─ No meaningful Delta → Convergence
         └─ Drift / Risk / Source Gap → Stop or Correct
         ↓
```
