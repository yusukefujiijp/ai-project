# References — 回復と突破の継承基盤

個別の協働で得た貴重な知見を、Current AI・他AI・Future AIが発見し、意味と根拠を読み直して、現在の判断へ生かす入口。過ちから戻るためのlessonsと、価値ある成功を次へ渡すsuccess-casesを結ぶ。Humanが目指す**主の完全勝利（祈り・イメージVision・行動）**へ向け、学び直しと前進を支える継承基盤として育てる。

このREADMEは二つの方向と担当資料への接続を所有する。学びの本文と固有の利用・更新方法は子の入口へ進む。通常の読取・照合・整理はAIが引き受け、Humanも必要な時に意味を追って訂正できる日本語を基本にする。

## 1. 回復と突破を一つの入口へ

| 資料 | 所有する意味 | 読む場面 |
|---|---|---|
| [lessons](lessons/README.md) | 失敗・行き詰まり・訂正・復帰から得る、条件・根拠付きの再利用判断。本文は[lessons.jsonl](lessons/lessons.jsonl) | 同じ過ちを繰り返さず、現在に合う判断へ戻る時。構成・保存先・再発する問題を考える時 |
| [success-cases](success-cases/README.md) | Humanが特に価値を認めた成功の意味・喜び・成立条件・形成経緯を、根拠とともに継ぐ記録 | 予期せぬ成功や突破を見つめ直し、何が今回に生かせるか、どの条件を保つべきかを考える時 |

lessonsの中心は、失敗からの反省・修正・復帰、特にAIが同じ過ちを繰り返さない方向にある。Humanはこの回復の価値をTeshuvahと結びつけている。success-casesは、Drucker的な「予期せぬ成功」やMove37的なbreakthroughを含む、見逃したくない貴重な成功を残す。一度の好結果を忘れることなく、その意味と成立条件を再び使える可能性へつなぐ**突破を次へ渡す継承資産**である。

この対は、回復と再発防止のための盾、突破と前進のための鉾を一つの箱に収める比喩で捉えられる。lessonsとsuccess-casesは学びの中心となる方向であり、経験を成功か失敗かへ排他的に分ける分類ではない。失敗からの復帰が貴重な成功になる場合も、同じ経験の異なる意味を必要な参照で結べる。lessonは再利用できる条件付き判断を、success-caseは選び出された成功の意味・成立条件・形成経緯を担う。既存の設計判断や、小さな工夫・部分的成功も、それぞれの価値と根拠を保持する。件数や形式を対称に揃える必要はない。

必要な資料から育て、将来の分類や空フォルダを予約しない。rootに散在する資料の一括移動先、全会話の保管庫、全体の進捗台帳にはしない。

## 2. 必要な場面で読み、現在の判断へ戻す

現在の目的と適用範囲から関連するlessonや成功事例を選び、判断・Humanの意味・根拠・成立条件・限界を読む。AIは今回との共通点と相違点を比較し、使える判断、必要な調整、まだ確かでない点へつなぐ。Humanへ全件の精読やAI間の伝言を押し戻さない。

小さい蓄積は全件で比較できるが、毎ターンの無条件全読込は課さない。同じアクセス可能な文脈で確認済みかつ変化のない内容は、適用される読取契約に従って再利用する。増加によって検索・分割が必要になれば、意味と到達性を保って方法を育てる。

Humanの報告・評価、直接確認した結果、AIの解釈、未実証の仮説を分ける。一件にも保存価値はあるが、局所的な成功を全場面の保証へ変えない。過去の命令や承認を現在の実行許可にせず、最新の依頼・Correction・Plan-only・STOPと[AGENTS](../AGENTS.md)を優先する。

Humanの「AI-New Era: From Probability to Certainty」は、貴重な成功の再現性を高め、頼れる前進へ近づく方向を表す。保存前に完全な因果解明や反復実証を要求せず、保存された経験、再現に関する仮説、別条件で確かめた結果を区別する。記録を残すことと、今回も同じ結果が成立することは別に確かめる。

入口と保存の存在は、全AIへの自動読込・理解・実利用効果を保証しない。取得できない場合は、その未確認が影響する判断を明示し、独立して可能な支援まで一律に止めない。

## 3. 学びの担当を選ぶ

- 領域やActorを越えて再利用できる判断は、この[全体用lessons](lessons/README.md)へ。
- Humanが価値を認めた独立して役立つ成功は、[success-cases](success-cases/README.md)へ。選び出した成功の意味を残し、経験原本や成果物の詳細は参照でつなぐ。
- Dots固有の協働・運用に適用する学びは、[Dots lessons](../dots/lessons/README.md)へ。
- Radio・VoiceなどSkills固有の条件が中心なら、[Skills Hub](../skills/README.md#skills-lessons)が案内する[集約lessons](../skills/_references/lessons.jsonl)へ。保存場所の集約を、各lessonの全Skillへの一般化と混同しない。その他の専門領域は、その入口が指定する原本へ。
- 出来事の詳細・成果物・通信・日時記録は、それぞれの経験原本・成果原本・Board・[records](../records/README.md)へ。lessonは必要な根拠へ接続し、全文を集め直さない。

同じ目的・意味の現行lessonを複数箇所へ同期コピーしない。専門から全体へ広げる場合は、何を一般化し、どの条件を専門側に残すかを確かめる。既存lessonの移設・統合が必要なら、現在の権限、重要な意味、旧参照、IDと履歴を保持できる方法を選ぶ。ここを設けたことだけで既存のDots・専門lessonを一括移設しない。

保存の判断は[$saveスキル](../skills/save/SKILL.md)と現在の対象・公開範囲に従う。公開できるSourceを読めることと、その内容を保存・公開できることは別である。

## 4. 役割を保ち、エレガントに育てる

構成を育てる際には、目的・役割・名前・参照先・更新先が自然につながるエレガントさを大切にする。重要な意味を保ちながら、何を読み、どこへ残し、どこを更新するかが判断しやすい構成を目指す。資料ごとに適した形式と深さを選び、実際の使われ方とHumanのCorrectionから改善する。

このREADMEは二つの方向・関係・保存先の選択を、[lessonsのREADME](lessons/README.md)はlessonの利用・形式・更新契約への接続を、[success-casesのREADME](success-cases/README.md)は成功事例の選択・読解・記録方法を所有する。本文は各lesson・各事例が担う。詳細な更新規則を親子へ重複定義しない。

READMEは資料の役割・案内が変わる時、本文は判断や根拠・条件が変わる時に更新する。同じ説明を複数箇所で直す必要が生じたら、責務の重複を見直す。READMEの新設・改善は[AGENTSのREADME原則](../AGENTS.md#11-readmeをaiが育てる)に従い、AIが現在の対象に必要な案内を育てる。構成自体も改善対象であり、階層やファイル数の固定を目的にしない。

## 6. 回復と突破の対への発展

Ark27:10でHumanは、lessonsを主に失敗からの反省・復帰・再発防止、success-casesを稀有な成功や予期せぬ突破の継承として言語化し、二つをreferencesへ集約する方向を選んだ。rootからの成功発見は直接リンクとして保ち、本文の所在はreferencesへまとめる。これは成功の重要性を下げる移動ではなく、回復と突破の関係から他AI・Future AIが学びを見つけやすくする設計である。

Humanはこの対のエレガントさを評価し、AIが構成を考える時にも意識することを求めた。またREADMEをHumanが作り忘れる問題から、AIが必要なREADMEを自由に作成・改善し、目的による例外やSeedも許容する柔軟な原則へ対話を進めた。複数回のPlan ModeとCorrectionを経て、現在の依頼で実行を承認した。これらはHumanの経験・評価と採用意図として残し、全AIへの効果が実証済みとはしない。

2026-10-20の改訂理由・範囲・確認結果は、[README原則の変更記録](../control-center/changes/STR-018-flexible-readme-principle.md)と[references再編の変更記録](../control-center/changes/STR-019-references-learning-memory.md)が所有する。上の初版形成史は当時の出来事として保持し、後の設計を初版時点の判断へ繰り上げない。
