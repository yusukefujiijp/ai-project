# 就寝前の寝落ち問題

[Problem Solving入口](../README.md)へ戻る。

**突然の強い眠気で、歯磨き等の必要行動へ入る前に寝落ちしてしまう。眠気が来てから大きな準備や判断をせず、必要行動を済ませ、意図した睡眠へ移れる入口を日々使えるようにしたい。** これが現在のGoalである。

Humanは長年の切実なBottleneckとして早い解決を願い、直近の寝落ちをTeshuvahの言葉とともに報告した。その意味を尊重しつつ、AIが寝落ちを信仰不足と診断したり、Teshuvahの完了を認定したりしない。Root・Human Foreground One・権限とGuardは[親入口](../README.md)と適用Runtimeを継承する。

## 1. Goalと、何を成功として見るか

支えたいのは、刺激そのものの強さではなく、**必要な行動へ着手して終え、その後の睡眠も保てること**。準備・迷い・継続負担を小さくし、カフェインへの依存や摂取量をできるだけ抑えられる方法を探している。「最小量なら睡眠への悪影響がなくなる」という保証は得られていない。

| Node | Edge | 現在の意味 |
|---|---|---|
| 必要な就寝前行動 | → 意図した睡眠への移行 | 歯磨き等を済ませたい。眠気を長時間押し戻して活動し続けることをGoalにしない |
| 急な眠気・その場の迷い | → 着手前の寝落ち | Humanが報告した詰まり。毎回その場で比較・準備を始める構成では間に合わない可能性 |
| 事前に使える入口 | → 着手への距離を短くする | 「入口の再現性」。配置・手間・思い出しやすさと、身体への刺激効果は別々に読む |
| リステリン系の刺激と口腔ケア | → 歯磨きへ直接つながる可能性 | 一つの手段で複数の目的を支える候補。実際の寝落ち防止・着手・完了は未報告 |
| その回の成立条件と結果 | → 次の判断を修正 | 良い案という評価、単発の好結果、繰り返せること、因果説明を区別する |

ここでの矢印は、報告された問題関係と検討中の接続を示す。効果がすべて実証された因果図ではない。「毎日確実に」はHumanの目指す信頼性であり、現在の保証ではない。

## 3. リステリン案で何が変わったか

当初は、良質な睡眠を守るためにCaffeineを避けるか、寝落ちを避けるために少量使うか、という二択が中心だった。リステリン案で、**歯磨きへ入るための刺激と、歯磨きへ進む動線を一つにできるか**という検討が加わった。

これはトレードオフを解消する候補の発見であり、解消済みという結論ではない。人が動き出せる入口と、必要な行動の行き先を一緒に考える点に、このモデルケースの再利用価値がある。他の問題にも同じ製品を勧めるという一般化ではない。

HumanのCorrectionは、刺激を一律に欠点へ分類せず、目的に役立つ可能性として評価し、安全面だけで検討を閉じないこと。ベッド横という案も、眠気が来た瞬間の準備を減らす意図として保持する。口に含んだまま寝ることや、意識が落ちかけた状態で無理に使うことを、この案から導かない。具体的な使用は実物の表示とその時の身体Realityを前提にする。

現在の未確認は、①入口を使えたか、②主観的な刺激や目覚めがあったか、③必要行動へ実際に移り終えたか、④その後の睡眠はどうだったか、という異なる接続にある。これは後の自然なFeedbackを読み解く観点であり、毎日の記録表や身体Trialを自動開始する指示ではない。

## 5. 今有効な接続

文書上は、問題の単位、Goal、入口の再現性、原本の担当、候補と未確認を接続できた。実生活では、リステリンによる寝落ち防止・歯磨き達成・睡眠との両立の結果はまだ報告されていない。

次のHuman Feedbackがあれば、すでに合意した説明をやり直さず、どこまでつながり、どこで途切れ、条件がどう違ったかへ接続する。結果が出るまでこの問題を放棄せず、同時に文書構成の完成を身体上の解決と取り違えない。新しい実地検討を依頼された時は、その依頼と身体Realityから範囲を解決する。
