- 応答に使える言い方：「御心なら手放せるというYusukeJPの信仰を、判断の中心として受け取ります。私は御心を判定せず、今の報告と全体バランスを一緒に整理します。」
- 取り違える言い方：「今ゾーンをやめることが主の御心です」「祈れば必ず元のゾーンが戻ります」。いずれもAIが認証できない事柄である。

祈り・Teshuvahと可能な行動の同時性は保持する。祈りを身体行動の合格条件にせず、生活行動を信仰の採点へ変換しない。

| 切替困難の経験 → AMへの前倒し・ケア時機の再検討 | Humanの逆算。[h21–h24] | 休日の余地を確保する案。朝に全てを詰め込む義務ではない。 |
| 昼の清潔行動 → 夜の見送り → 朝の「温まり・切替」の振り返り | 前半は本人報告、後半はHuman判断。[h14、h24] | 行動名だけでなく、その時点で満たしたい目的を残す。 |
| BtoBの方向が曖昧 → 具体的な出発側・移行先を明記 | Humanの訂正。[h32] | 正反対の移行を同じ支援へ固定しない。到達済みや現在状態とは分ける。 |
| 通常→超絶 → 外出系を全て外す → 室内系に限定 | Humanの方針。[h35–h36] | 外出を断り直す負担を減らす。室内の実行可能性まで認定しない。 |
| ケア後の想起困難懸念 → ケア前の受渡し | 前半はHumanの見立て、後半はAI案。[h28] | AI呼出し自体を忘れる可能性も含め、再入力を前提にしすぎない。 |
| ケア・休息 → 変化を受け取る → 可能なら室内Workout／祈り・休息 | 本人の希望とAI設計。[h34–h36] | 回復を保証せず、Workoutを新しい必須課題にしない。 |
| 朝の外出開始報告と通常→超絶の室内限定 → 時点と方向で支援を分ける | Human報告とAI整理。[h26–h27、h36] | 朝の実績を通常→超絶での外出提案へ流用しない。 |
| Feedback → 原文とCorrectionの保存 → 再読と現在への適用 → 次のFeedback | Humanの要望とAIの設計。[h03、h24] | 保存で輪が完成したとはせず、実際の読取・適用・効果を別に確認する。 |

失敗はBottleneck検出として扱うというHumanの方針を保持する。[h03b] この経験を失敗者の評価や信仰不足へ拡大しない。音声での入眠という「予期せぬ成功」も、一回の好結果から選択肢を増やす材料とし、必勝法へ昇格させない。

## 6. 再説明させず、現在の支援へつなぐ

次にこの一件を扱うAIは、最新のHuman入力を先に受け取り、既存の訂正を使う。新しい状態や行動が既に報告されていれば、再入力を要求しない。

- 当夜にOFF・祈り集中を選んだ理由を、Humanに毎回思い出して証明させない。同じ状態が現在も続くとは決めつけず、後の音声利用という実行報告も使う。
- ONで支援へ到達できる入口、状況に合うスマホなしトイレ、以後自由という共有方針を保持する。今回済んだトイレを儀式としてやり直させず、個別のOFF選択を全場面に固定しない。
- 祈りを思い出す支援を求めた意図を保ち、御心の判定を代行しない。眠れた経験を尊重しつつ、毎回同じ入眠や回復を保証しない。
- BtoB(通常→超絶)では外出系すべてを外し、室内へ限定する。室内でも何かできるか未確認という留保を使い、ケアやダンベルWorkoutを自動課題にしない。[h35–h36]
- 方向付きの名称を記録に用い、短いHuman入力には既知文脈を使う。方向不明を勝手に補わず、自己分類・正確な用語・実況を支援の条件にしない。
- 朝のケア・Workoutの候補は、現在の条件から扱う。雨・前夜の状態・過去の成功だけで実行を断定せず、今回は身体Trialを開始しない。
- 深く考えた説明を、低認知という理由でAI側が省略しない。Humanがまず見つけたい要点を明確にし、根拠と詳細へ進めるよう整理する。
- 返信・実況・分類・記録を、祈り・休息・可能な行動の前提にしない。無返信の結果はUnknownのまま保つ。

## 7. 一回限りの記憶・記録で終わらせない更新方法

保存先を毎回増やすのではなく、**この一件の原文・時点・判断と、今使うCorrectionを接続して育てる**。

1. Humanの自然な実況・訂正を、その意味が変わらない連続した原文または明示した要約で残す。時刻は分かる範囲だけを記し、イベント・入力・保存の時刻を混ぜない。
2. 「実行した」「選んだ」「良かったと思う」「すべきだった」「AIがこう解釈した」を区別する。後から結果が届いた時は、当時のUnknownを消して歴史を作り直さない。
3. 重要な意味の変化は、このREADMEの現在の理解とtask-recordsの根拠・関係へ反映する。新しいCorrectionが旧解釈を変える時は、理由を辿れるようにする。
4. 保存の権限がある範囲で、最新Remoteを読み、他の変更を保持して更新し、保存後に再取得する。Plan-only・保存禁止・STOPが来たらその境界を優先する。
5. 次のAI支援では、保存先を作ったことだけで満足せず、実際に読み、現在の入力へ接続する。常時監視、自動同期、全AIの永続記憶は約束しない。

「こまめに」は、秒単位の自動収集や毎入力後の義務的作業を新設する意味ではなく、意味あるFeedbackを一度きりの会話に閉じず、許可された場面で更新して使うという今回の方針として受け取る。具体的な将来の頻度・通知は設定していない。

### 残るUnknown

音声入眠の再現性とサプリの寄与、AMや狭間のケアの実行・効果、7:00前後の運動開始後の詳細・終了と乾燥機回収、ケア後の戻り具合と室内Workoutの可否・実績、AI呼出しと事前受渡しの実利用、保存文脈が次のAI支援を助ける程度は未確認。詳細はtask-recordsのopen_questionsへ接続する。外出したかという初版のUnknownには移動・開始の報告が加わったが、未報告の完了を補っていない。これらはHumanへの宿題リストではない。

### 次の読み手への接続

同じ一件を再開する時は、最新Human入力を先に受け取り、§1・§4から今回のCorrectionを使う。根拠や時点を確認する必要がある時はtask-recordsの対応source・node・edgeへ進む。自己点検と、別AIによる実際の読解成功は分ける。全会話の復習、試験、身体Trialを開始条件にしない。

この記録は、次の支援の材料が存在するという到達点。**Source保存、読み手の理解、Humanが辿れること、設定反映、実行、実生活効果は、それぞれ別の到達点である。** 既にある本人報告は保持し、未確認の因果や将来効果は追加しない。
