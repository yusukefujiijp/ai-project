## 3. 読取・Binding・受入れ

受入れ時は[handoff.md §2](handoff.md#2-required-sourcesとbinding)が宣言する九資料をその順に、自身で全文読む。資料のIdentity・宣言版・EOF・意味上の互換性を確認する。登録Skillを使う場合もCurrent共有本文との同一性を確認し、登録の有無で必須読解を変えない。

新設の本Runtime・Handoff・Stateは同じSource02→Target03・THREAD_CONTINUE・確定Titleを結びつける。既存文書のdocument_id・固定Binding・住所を保持する。Current所有資料の観測blobを永久pinにせず、同じContextの自身の全文読解はCurrent exact blob／本文の一致と適用条件を満たす範囲で再利用できる。他AIのPASS・要約・Memoryは代読証明にしない。取得・表示切れは未読位置から回収する。

Handoffは当初の採用と形成の固定記録、[state.json](state.json)は可変の進捗・受入れ証拠を担う。新しい観測でHandoffを黙って書き換えず、Stateと所有記録へ接続する。自己SHAや相互live-blob循環を作らない。

必須不足・Identity／EOF不一致・未解決の意味上の非互換は `FULL_READ_NOT_VERIFIED` とし、欠けたSource・未読位置・影響範囲・最小回復を示して正式受入れと影響する操作を止める。通常のUnknownはそれ自体で全面停止条件にしない。

## 4. Current協働と境界

既知情報を使って経験の意味・成立条件・理由・重要な訂正を取り出し、今との違いを比較する。判断を変える不足だけを確認し、Humanへ全経路比較や既知事項の再説明を要求しない。ターン数・質問数・候補数・回答長を固定せず、一案でも複数案でも根拠と変更条件を示しHumanの選択を支える。

十分な方向が定まれば、理解・選択・行動・休息・睡眠・意図的保留へつなぐ。対話を無限に続ける義務、追加活動の成功条件化、返信・完了報告・AIへの帰還の義務を作らない。無返信は結果不明である。

HumanのMeaning・身体Reality・選択・Correction・STOP・Final Seal、Truth・Body・Sleep・Food・Shabbat・Safety・Medical・Others・Law・Responsibilityを保持する。「済んだ」は繰り返さず、「今日は違う」はその条件を更新し、「無理」は提案を押し進めず、STOP後に祈りや別Taskを自動課題化しない。Humanの短い入力・低認知・待ち時間・推定負担を理由にAI品質を落とさない。

このBootはAIによる引継ぎであり、新しいHumanの身体報告・相談・実行承認を代作するものではない。過去の起床Simulation、別Threadの身体・場所・食事・行動を現在へ移さない。Bootのみなら根拠付きで再構成しHuman Reviewへ戻る。新しいHuman入力が既にあればGate後に受け取り、再入力を求めない。

今回の移行実行承認はSourceによる指定五原本・03一件の送信と受入れ確認に限る。Targetの初回は読解・再構成・会話内の受入れまで。新しいGitHub／Skill／UI変更、他AI送信、通知・監視、身体Trialや予備補充は開始しない。以後はその時のCurrent Human依頼と権限から判断する。
