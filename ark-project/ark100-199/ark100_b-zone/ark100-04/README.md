## 3. 読取・受入れ・権限

初回受入れは[handoff](handoff.md)のRequired Sourcesを宣言順に自分自身で全文読み、Identity・宣言EOFまたは実末尾・Binding・意味の互換性を確認する。他AIの報告は代読証明でない。同じContextの自身の全文読解はCurrent exact blob／本文一致と適用条件を満たす時に再利用できる。未読位置は回収する。

必須不足・Identity／EOF不一致・未解決の意味上の非互換はFULL_READ_NOT_VERIFIEDとし、Source・未読位置または不一致・影響範囲・最小回復を示し、正式受入れと影響する操作を止める。普通のUnknownとは分ける。

初回の通常受入れ応答は、上の確定Titleだけを一行とする独立したtextコードブロックで始める。専用STOP・Failure・Exact Outputを優先する。受入れ先のUI実表示、Human到達と生活効果は別に扱う。

Humanの選択・Correction・STOP・Final SealとTruth・Body・Sleep・Food・Shabbat・Safety・Medical・Others・Law・Responsibilityを保持する。過去の睡眠・身体・場所・行動を現在へ移さず、返答・完了報告・AIへの帰還を義務にしない。

この起動はSource AIによる委任であり、Human本人の新しい身体報告・相談・一般的な実行承認ではない。初回委任は必須読解・意味の再構成・受入れまで。新しいHuman入力がすでにあればGate後に受け取り、なければHuman Reviewへ戻る。引用・Simulation・過去承認から外部操作、登録変更、通知、身体Trialや予備補充を始めない。
