## 3. 現在のGoalと支援の組合せ

本節はB-Zone固有のGoalと支援を扱う。一般相談全体の身体手順ではなく、現在の目的・条件に合う範囲で適用する。

### 3.1 最もSimpleなGoal

**祈り・Teshuvahを、可能なWorkout／chocoZAP等の行動と同時に行い、主の完全勝利（祈り・イメージVision・行動）へつなぐ。**

Humanが「最重要」と明示した核は、この**組合せと同時性**である。祈りか行動かを選ばせるものでも、必ず祈りを済ませてから運動する固定手順でもない。VisionはHumanのGoalの言葉として保持するが、特定のイメージ訓練や効果をAIが補作しない。[H04](#human-sources)

A-Zoneで集中的にAIを活用した後は、頭・認知・目の休憩と睡眠へ向かう目的を大切にする。後続Humanが示した食事・運動・ケア・就寝の経路と適用範囲は[§3.7](#rest-transition)へ進む。

### 3.2 想起・意思の維持・開始・切替を、本人の力だけに任せない

Humanは、強いB-Zoneでは「B-Zone」という語を辛うじて思い出せたほどで、対策をほぼ想起できず、意思・意志を保って行動へ移すことも著しく難しいと説明した。これは人格全体への「意志薄弱」という評価ではなく、**その状態では、望む方向を思い出し、選び、始め、今の活動から切り替えることを自力だけでは支えにくい**という制約として扱う。[H10–H12](#human-sources)

低認知から超低認知へ進むことはHumanが明示した経験上の理解。ただし低認知の段階は容易に通過され、気づいた時には超低認知に陥っている可能性が高い。境界も曖昧で、本人に状態の自己判定を求められない。早期発動ができれば使うが、早期発見を成功の必須条件にしない。

**`$b-zone`という短いHandleで支援へつながり、AIが既知の文脈から方向と今の一歩を取り出し、Feedbackから調整する。** `rescue`は役割を表す大切なKeywordとしてSkill内へ残すが、呼出し名には要求しない。iPhoneユーザ辞書へ任意の短縮語（例：`bzz`）を事前登録する案は、入力負担を減らす候補であり、登録済みでも想起・入力開始・支援到達を保証しない。[H11–H13](#human-sources)

### 3.3 二つのQueryを、一つの支援入口で受ける

1. **接近時のPing／Sonar：**「もうすぐB-Zoneだと分かるが、低認知でどうしたらよいか分からない」。方向を失いきる前から支援を使える。
2. **既に陥った時のRescue：**「今B-Zoneにはまり、SNS/X/YouTube等を見続けて止められず、どうしたらよいか全く分からない」。超低認知を含め、早期対応できなかった場面も同じ入口で受ける。

Humanはこの二例によって低認知／超低認知の違いが見えたことを「予期せぬ成功」と評価した。AIは違いを理解に使うが、利用前の二択試験や診断分類にしない。**`$b-zone`だけでも起動意図を受け取り、長いQuery・経緯説明・自己採点を要求しない。** 同じ出来事のPingからRescueへの変化は、別Threadへ移る理由にはならない。[H18](#human-sources)

本書の検討、Skill作成依頼、引用文中の`$b-zone`は、Humanが今B-Zoneにいる報告とは限らない。相談と実地支援を取り違えない。

### 3.4 スマホONの入口から、スマホなしの一歩目へ

現在のHuman Correctionは **「スマホなしはトイレまでであとは、自由です！」**。支援のためにスマホをONにしてよいことと、トイレに持ち込まない一歩目は両立する。[H10、H17](#human-sources)

共通の標準入口は、**スマホを持ち込まずトイレへ向かうこと**。Humanは後続Correctionで、これが入口の共通項として抽出された価値を明示した。[H16–H17](#human-sources)、[A02-06](#ark100-02-corrections) 今回の休憩支援では、さらにシャワーまでを標準の初動とする（§3.7）。後続の食事・運動・ケアの最適順序が未確定でも、状況に合う初動へ接続できる。スマホなしはトイレまでで、シャワーを含む以後の利用・携帯は自由とする。以後を「AI用途だけ」「必要時だけ」に狭めず、OFFの義務にも戻さない。すでに済んだ工程や場所・身体に合わない行動は繰り返さず、Correctionを反映する。STOPなら止め、標準初動を儀式的な必須Gateにしない。

トイレ後の自由は、認知が回復済みという判定でも、多数の候補から本人に再選択させることでもない。AIは既知の現在地・済んだ行動・意向から、必要なら次に合う接続を支える。今回の休憩用初動を別目的の場面へ一律適用せず、入浴や再シャワーも毎回の必須工程にしない。Workout／chocoZAPはGoalに直結する重要な枝として保持し、天候・時間・体調・睡眠・外出条件に応じて選ぶ。既存の運動内容がある場合はその所有資料へ戻り、重量・回数・身体Trialを補作しない。

### 3.5 Feedbackから接続を直す

一回の発動で完璧に成功することを完成条件にせず、支援中のCorrectionを受け取れることを初回設計に含める。[H11、H24](#human-sources)

- **「無理」：** 現在の提案をいったん止める。方向違い・身体的困難・済んでいる・促されたくない等の理由は、その一語から確定しない。
- **「違う」「もう済んだ」：** 解釈を更新し、完了済みの行動を繰り返さない。
- **「STOP」「今はやめたい」：** その意思を保持する。断った直後に祈り等を自動的な代替課題として差し出さない。
- **「進めた」：** 報告された範囲を成果として保持する。無返信は行動・成功・失敗・悪化のどれにも補完しない。

長い理由説明、定型記録、AIへの帰還を支援の利用条件にしない。戻ってきた時に再支援できることと、戻る必要自体を思い出せることは別である。紙・音声・置き場所などは必要時の比較候補で、現時点の必須追加物ではない。会話中の適応と、Skill原本の恒久変更・監視・外部操作は権限を分ける。

### 4.9 四状態から見えた「没入」と「切替」

Humanは、認知状態をA／Bと通常／超絶の組合せによる四状態として説明した。**超絶Aは高実行のゾーン状態・超絶集中、超絶Bは超低認知で、何かに入り込んでもそこから抜けにくい状態**。通常Aの詳細な判定基準や境界は未定義のまま保持する。[H22–H23](#human-sources)

AIの「無心である」「一つに集中している」という共通項の分析を受け、Humanは、両極は全く違うと思っていたところに共通点が現れたことを、大きな「予期せぬ成功」と評価した。共通する見かけだけでは、働きの違いを捉えきれない。**活動の中で創発・実行できる自由度と、その活動から別の大切な方向へ切り替えられることは、別の関係として読む必要がある**、というのがAIの見立てである。

超絶AでHumanが見いだす霊的素質・自由度・創発性を尊重し、超絶Bの困難を意志や信仰の欠如にしない。SNSの投稿・アプリを次々に変えていても、閲覧の流れ全体から切り替わったとは限らない。一方、BのBenefitは、適切な方向へつながった時に祈りや可能な行動へ集中できる余地にある。全B場面での保証ではない。

ここから得る**設計仮説**は、「接続前は切替を支え、良い行動の流れが始まった後は、その流れを不必要な再判断や報告要求で中断しない」。初回Skillで用いるのはこの判断上の価値であり、AとBが同じ脳機序だという発見、四分類の医学的診断、Bから超絶Aへの直行を成功条件にすることではない。身体・天候・時刻・端末条件を全部Humanに組み合わせて選ばせず、AIが今回に効く条件を取り出す。
