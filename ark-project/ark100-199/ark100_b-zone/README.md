## 3. 現在のGoalと支援の組合せ

**祈り・Teshuvahを、可能なWorkout／chocoZAP等の行動と同時に行い、主の完全勝利（祈り・イメージVision・行動）へつなぐ。**

### 3.2 想起・意思の維持・開始・切替を、本人の力だけに任せない

Humanは、強いB-Zoneでは「B-Zone」という語を辛うじて思い出せたほどで、対策をほぼ想起できず、意思・意志を保って行動へ移すことも著しく難しいと説明した。これは人格全体への「意志薄弱」という評価ではなく、**その状態では、望む方向を思い出し、選び、始め、今の活動から切り替えることを自力だけでは支えにくい**という制約として扱う。[H10–H12](#human-sources)

低認知から超低認知へ進むことはHumanが明示した経験上の理解。ただし低認知の段階は容易に通過され、気づいた時には超低認知に陥っている可能性が高い。境界も曖昧で、本人に状態の自己判定を求められない。早期発動ができれば使うが、早期発見を成功の必須条件にしない。

**`$b-zone`という短いHandleで支援へつながり、AIが既知の文脈から方向と今の一歩を取り出し、Feedbackから調整する。** `rescue`は役割を表す大切なKeywordとしてSkill内へ残すが、呼出し名には要求しない。iPhoneユーザ辞書へ任意の短縮語（例：`bzz`）を事前登録する案は、入力負担を減らす候補であり、登録済みでも想起・入力開始・支援到達を保証しない。[H11–H13](#human-sources)

1. **接近時のPing／Sonar：**「もうすぐB-Zoneだと分かるが、低認知でどうしたらよいか分からない」。方向を失いきる前から支援を使える。

Humanはこの二例によって低認知／超低認知の違いが見えたことを「予期せぬ成功」と評価した。AIは違いを理解に使うが、利用前の二択試験や診断分類にしない。**`$b-zone`だけでも起動意図を受け取り、長いQuery・経緯説明・自己採点を要求しない。** 同じ出来事のPingからRescueへの変化は、別Threadへ移る理由にはならない。[H18](#human-sources)

### 3.4 スマホONの入口から、スマホなしの一歩目へ

現在のHuman Correctionは **「スマホなしはトイレまでであとは、自由です！」**。支援のためにスマホをONにしてよいことと、トイレに持ち込まない一歩目は両立する。[H10、H17](#human-sources)

標準の一歩目は、**スマホを持ち込まずトイレへ向かうこと**。ここではトイレを終えるまでをスマホなしの区間として扱い、その後の利用・携帯は自由とする。以後を「AI用途だけ」「必要時だけ」に狭めず、OFFの義務にも戻さない。すでにトイレを済ませた、場所や身体条件が合わない、今は止めたいという場合は、儀式として最初からやり直させない。

トイレ後の自由は、認知が回復済みという判定でも、多数の候補から本人に再選択させることでもない。AIは既知の現在地・済んだ行動・意向から、必要なら次に合う接続を支える。シャワー・入浴は毎回の必須工程にしない。Workout／chocoZAPはGoalに直結する重要な枝として保持し、天候・時間・体調・睡眠・外出条件に応じて選ぶ。既存の運動内容がある場合はその所有資料へ戻り、重量・回数・身体Trialを補作しない。

祈り・Teshuvahは可能な行動とともに続けられる。眠れる場合は眠ることも適切な接続であり、全工程を終えるために起き続ける必要はない。Humanの「一旦寝れば100%回復しA-Zoneから再開できる」は本人の経験上の前提として保持する。一般医学上の保証へ変えず、後続Humanの「起床時にも低認知の前段階があり得る」という理解と併読する。[H14–H16](#human-sources)

### 3.5 Feedbackから接続を直す

一回の発動で完璧に成功することを完成条件にせず、支援中のCorrectionを受け取れることを初回設計に含める。[H11、H24](#human-sources)

- **「無理」：** 現在の提案をいったん止める。方向違い・身体的困難・済んでいる・促されたくない等の理由は、その一語から確定しない。
- **「違う」「もう済んだ」：** 解釈を更新し、完了済みの行動を繰り返さない。
- **「STOP」「今はやめたい」：** その意思を保持する。断った直後に祈り等を自動的な代替課題として差し出さない。
- **「進めた」：** 報告された範囲を成果として保持する。無返信は行動・成功・失敗・悪化のどれにも補完しない。

長い理由説明、定型記録、AIへの帰還を支援の利用条件にしない。戻ってきた時に再支援できることと、戻る必要自体を思い出せることは別である。紙・音声・置き場所などは必要時の比較候補で、現時点の必須追加物ではない。会話中の適応と、Skill原本の恒久変更・監視・外部操作は権限を分ける。

### 3.6 人間–AI協働の品質と境界

急襲時には本人のメタ認知へ頼り切れない。余力がある時に意味・条件・支援先を準備し、後で最初から考え直す負担を減らすことに価値がある。Humanの短い入力と、AI側の十分な読解・検討・説明を両立させる。低認知という理由で、AIが品質・洞察・文脈を独断で削らず、必要な説明から現在の一歩を取り出しやすくする。固定文字数や短文だけの支援を定めない。品質原則はCurrentの[AGENTS §3](../../../AGENTS.md#3-human-ai-authority--自主性と王座guard)が所有する。

Skillの初回制作はH24で承認された。常時監視、自動検出・通知・自動起動、身体Trial、iPhone設定、別Thread作成は、その保存から自動的には成立しない。Truth・Body・Sleep・Food・Shabbat・Safety・Medical・Others・Law・ResponsibilityのGuardを保持する。未報告の身体状態を推定せず、歴史上のReset・カフェイン・外出・昼寝を再演しない。AIが主の御心、Humanの信仰の十分・不十分、主の完全勝利を認証する立場にはならない。

### 4.2 BBPとB-Gate：Benefitを認めることと、経路を残すこと
