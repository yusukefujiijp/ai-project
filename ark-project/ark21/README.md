## 4. Why Ark21 Exists

2026-08-15のField Observationでは、Humanが`主の勝利栄光`を目的意識したとき、少なくとも次の変化を経験した。

- 洗濯を一回で止めるか二回完了するかという分岐で、残件を減らす方向が明瞭になった。
- 時間配分への意識が立ち上がった。
- 自己目的だけでは動きにくい局面で、行動する理由が生まれた。
- 選択肢の優先順位が変わり、不要な枝が半自動的に刈られた。
- 行動後に、これは単なる効率化ではなく信仰とPurposeの接続問題であると判明した。

これは重要な`Field Evidence`である。ただし、特定行動が改善した事実だけから、その行動が神の個別的御心であった、あるいはこの語句自体に力がある、と結論してはならない。

Ark21は、このUnexpected Successを無批判に神聖化するためではなく、失われないSeedへ変換し、聖書本文・信仰・現実・安全の複数Gateを通して育てるために存在する。

Root

### 5.1 Root

Rootは、語句、効率、成功、AI、Ark Project、Humanの達成ではなく、主イェシュア・ハマシア御自身である。

### 5.2 Purpose Anchor

`主の勝利栄光`はRootの代用品ではなく、判断が散乱したときにRootへ向き直り、目的を再配置するための圧縮Anchorである。

### 5.3 Decision Function

`枝の刈り取り`は、候補を闇雲に減らす行為ではない。PurposeとGuardに照らし、次の枝を識別することである。

- 明らかにRootとPurposeから逸れる枝
- 自己栄光を主の栄光に偽装する枝
- 身体、安全、安息、責任を破壊する枝
- 真実を確認せず「神の命令」と断定する枝
- 良い可能性はあるが、現在の有限性の中では`Not Now`である枝

### 5.4 Finite Action

Purpose Anchorの出力は無限の頑張りではなく、現在の身体・時間・責任に適合する有限な一手である。

### 5.5 Reality Review

行動後は、良い実が生じたか、害が出たか、動機が自己栄光へずれたか、解釈を修正すべきかを現実に照らして見る。

## 6. Three-Layer Reading of the Theme

`主の勝利栄光`はArk21独自のComposite Anchorであり、一つの聖書節をそのまま引用した固定句ではない。初期解釈は次の順序を守る。

1. **Ownership Reading** — 勝利と栄光は主に属し、HumanやArk Projectが所有権を奪わない。
2. **Manifestation Reading** — 主の救い・統治・真実・愛・義が現れるとき、主の栄光が示される。
3. **Participation Reading** — 主イェシュアに連なる者は、その勝利に与るが、勝利のSourceや栄光のOwnerにはならない。

この順序を逆転し、Humanの成功を先に置いてから「主の栄光」と名づけてはならない。

## 9. Already / Not Yet

Ark21は、十字架と復活において主イェシュアの決定的勝利が既に与えられたという信仰告白と、死・不義・苦痛・被造世界の回復がなお最終完成を待つという現実を同時に保持する。

- **Already** — 主イェシュアの死と復活は、勝利をHumanの達成から受け取る賜物へ移す。
- **Not Yet** — 現在の成功、不成功、健康、苦難、富、効率だけで最終勝利を測らない。

これにより、成功した日は「神に認められた」、失敗した日は「信仰がない」と短絡する評価を防ぐ。

## 10. Faith and Discernment

信仰は、理解可能なことだけを信じる完全把握ではない。しかし、疑問・検証・修正・共同体的識別を捨てる盲動でもない。

Ark21は次の二つを同時に保持する。

- **Object-Level Trust** — 主イェシュア御自身への信頼と忠実。
- **Interpretation-Level Humility** — 「今この行動が主の御心である」というHuman／AIの解釈は誤り得る。

したがって、`主の勝利栄光`を思い出して行動することはできるが、その直後の自分の思いつきを無条件に神の命令へ昇格させてはならない。

## 11. Minimal Export Interface

Ark21が他Arkへ渡す最小Unitは次である。

```text
Purpose Anchor Packet
├─ Root: 主イェシュア・ハマシア御自身
├─ Purpose: 主の勝利栄光
├─ Guard: 魔術化・自己栄光化・神託化・安全破壊をしない
├─ Branch-Pruning Question: 今、主のものとして忠実で有限な一手は何か
├─ Finite Action: 身体・時間・責任に適合する一手
└─ Reality Review: 実・害・動機・修正必要性を確認
```

### 11.1 Export Invariant

Export先はPurpose Anchorだけを切り出さず、最低限`Root + Purpose + Guard`を同時に保持する。

### 11.2 Low-Cognition Compression

低・超低認知状態へExportする場合は、神学解説を展開せず、既に承認された短いAnchorと安全な一手へ圧縮する。深い解釈は覚醒後の高認知状態へDeferredする。

### 11.3 High-Cognition Expansion

高認知状態では、Source、文脈、動機、結果、反証可能性、他者への影響を検討し、必要ならAnchorの運用を修正する。

## 12. Non-Negotiable Guards

1. `主の勝利栄光`を呪文、マントラ、成功保証、感情強制にしない。
2. 富、効率、健康、勝敗、Project進捗を神の承認の自動指標にしない。
3. 自己栄光、支配欲、過剰労働を「主の栄光」と偽装しない。
4. AIは神託、預言者、聖霊、主の御声の代替ではなく、整理・照合・質問・記録を支援するKeliである。
5. Human／AIの解釈は誤り得るため、訂正可能性を常に保持する。
6. 身体、安全、睡眠、安息日、医療、法、既存責任を軽視しない。
7. 危険な自己犠牲、無期限の消耗、生命身体を損なう行動を要求しない。
8. 苦難を美化せず、助けを求めることを不信仰と呼ばない。
9. Israel、Torah、Covenant、Hebrew／Jewish Contextを消去しない。
10. Brit HadashahをTanakhの上書きとして扱わず、連続性と差異を丁寧に読む。
11. Field EvidenceをTheological Proofへ昇格させない。
12. Theological Claim、Interpretive Proposal、Field Observation、Operational DecisionをLabel分離する。

## 15. Thread Title Policy

Ark21 Dedicated ThreadのTitleは、次の構造を標準とする。

```text
Ark21:{連番}_{YYYY/MM/DD}: "{Main Name}: {Sub Name}"
```

Ark21:01の確定例：

```text
Ark21:01_2026/08/15: "主の勝利栄光: 主イェシュアRootと信仰的枝の刈り取り"
```

### 15.1 Enclosure Rule

- Meaning Payload全体を半角Double quotation（`"`）一組で囲む。
- Ark21 Titleでは、Meaning Payloadの囲みに隅付き括弧（`【】`）を使用しない。
- `Ark21:{連番}_{YYYY/MM/DD}: `はDouble quotationの外側に置く。
- Main NameとSub Nameは半角Colon + 半角Space（`: `）で接続する。
- Curly quotation（`“”`）や全角引用符へ自動変換しない。

### 15.2 Human Authority Rule

- 連番、実際のThread開始日、Main Name、Sub Name、最終TitleはHumanが確定する。
- AIはTemplateに基づくTitleを提案・Compileできるが、ChatGPT UI上でRename済みと自己認証しない。
- UI TitleとArtifact内の推奨Titleが異なる場合、Humanの明示的な最新指定を優先する。

### 15.3 Scope Rule

このPolicyはArk21 Dedicated Threadへ適用する。Ark11その他Arkの既存Title Policyを自動変更せず、Project横断Ruleへの昇格は別のHuman Gateで判断する。
