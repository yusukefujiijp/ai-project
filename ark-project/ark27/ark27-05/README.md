## 3. Humanの簡潔なI/Oと、AIが引き受ける内部

[Task Mode System](../../../task-mode-system/README.md)の主読者・運用者・保守者はCurrent AI・他AI・Future AI。Humanは短い報告・BrainDump・希望・訂正・Feedbackを渡し、使える成果を受け取る。内部資料、分類、Schema、参照管理、全件報告を利用条件にしない。

- **Task Mode**：意図と現場を扱えるTask、関係、優先順位、実行支援へつなぐ協働。
- **Task Records**：出来事・理由・Source・訂正・時点・Confirmed／Candidate／Unknownを保持する経験記録層。
- **Task Mode System**：協働と記録を、読解・対話・内部改善・次の現場への再接続まで機能させる仕組み。

AIは調査・比較・関係理解・記録・必要な保守を担う。必要な複雑さは許容するが、他AIが目的・条件・根拠・所有先を読んで運用できるようにする。Humanへの詳細表示量と、保持すべき意味・Evidenceの量は別である。理由への到達、重要なUnknown、進行・保存・停止、Correction・STOPの接点は残す。

一つの入口から全容を理解できることと、毎回全リンクを全文読解することは違う。System入口の初回・継続・一部文脈欠落の経路を使い、同じContextで確認済みの同一資料を再利用する。必須読解・Identity・EOF・Bindingの省略へ変えない。判断を変える条件が足りなければ所有資料へ戻り、揃ったら現在のHuman入力へ戻る。

## 4. 今回のHuman Material Corrections

### 4.1 問題解決優先の選択報告

YusukeJPは、時間・注意・利用枠を問題解決へ向けるため、順調な生活行動・既知の成功の逐次報告を意図的に省略する。問題報告が多いことから生活全体の不調を推定しない。確認済みの成果を土台として保持し、未報告の個別状態は成功にも失敗にも埋めない。

重要な成功や予期せぬ発見には保存価値がある。通常成功の反復報告を減らすことと、success-casesの価値は両立する。AIが依頼された外部変更について結果・重要な未完・保存確認を返す責任は減らない。根拠は[04原本](../ark27-04/task-records.json)の `selective-success-reporting`・`parallel-household-action-report`・`holiday-action-connection`。

### 4.2 開始時の締切理論

中心は、進行中の対話・思考・作業が**キリよく終わるのを開始条件にしない**こと。必要な判断ができ安全に移れるなら、扱える初手へ接続し、途中の文脈と未解決価値を保持する。開始時刻の指定だけへ戻さない。終了側がある程度機能するというHuman評価を背景に、開始側へ重点を移した。

全ての思い付きを即実行すること、現行責任やGuardの放棄、毎回答への身体Task追加ではない。実用上の条件は[共通運用](../../../task-mode-system/operation.md)§4.1、二重引用符付きSeedと形成根拠は04原本が所有する。

### 4.3 Token Resetと、成果の尺度

Reset跨ぎ後に新期間の残量が5％減ったというHuman報告を保持する。残量僅少でも処理が続くという情報と、旧期間への計上保証を分ける。サービス内部の正確な計上方式、残り3％等の万能な最適値は未確認。

週内配分と、期限前の余剰を有益な成果へ変える方法を改善する継続課題である。休日の現実行動が増えてAI対話時間が減ったという報告も需要予測を変える材料。利用枠を燃やすこと自体を成果にせず、05 Bootから新しい並列作業やReset実験を自動開始しない。
