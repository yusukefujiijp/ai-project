## 7. Triad・Binding・State契約

本書はHandoffを組み立てる前にRemote保存・本文照合を行う安定Runtime。Handoffは確認済み本書のblobを固定し、Source→Targetの初期化と有限の再構成条件を所有する。生成後の旧Handoffを可変Stateとして書き換えない。

state.jsonは`ARK27_04_CURRENT_STATE`、ownerはArk27:04、初期revisionは1。Source03と同じv001構成を用いる：`meta`／`identity`／`authority`／`bindings`／`now`／`evidence`／`deferred`／`progress`／`eof_sentinel`。metaのrevisionは正整数、owner・identity・runtime・Titleは本Runtimeに一致し、EOFは`ARK27_04_STATE_EOF_v001`。これはThread固有の既存構造の継続であり、Task Records Schemaではない。

Handoffから可変StateへはID・owner・schema_version・最低revisionで結び、更新可能なStateのlive blobを永久固定しない。Stateは本README・Handoff・章READMEの確認済みblobを保持し、自分自身のSHAを埋め込まない。変更後はrevision・理由・Evidenceを更新し、Remote照合する。Binding変更は明示的な整合経路で扱い、黙って緩めない。
