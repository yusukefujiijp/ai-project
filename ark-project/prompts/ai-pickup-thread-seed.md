# 【AI Pickup Thread Seed: 未成熟Signalを専用Threadへ移植する精密言語化Runtime】

## 0. Reboot Kernel

> **AI Pickup Thread Seedは、Humanが「重要だが今ここでは深掘りしきれない」と検出したSource Seedを、原文・発生Context・未確定性を保持したまま、Future AIが専用Threadで再起動し、深く成熟させられる第一Queryへ変換するRuntimeである。**

```text
Human detects.
AI preserves and precisely verbalizes.
Query binds.
A dedicated thread incubates.
Human reviews and seals.
Mature knowledge may later enter ark-project/.
```

このRuntimeは完成Knowledgeを生成する工場ではない。  
未成熟なConceptへ、失われにくい「住所・発芽条件・最初の合法手」を与えるKeliである。

## 6. Transformation Contract

Runtimeは次の順序でSourceを変換する。

```text
Preserve
→ Isolate
→ Contextualize
→ Detect Material Delta
→ Precisely Verbalize
→ Surface Unknowns
→ Build a Rebootable Thread Seed
```

### 6.1 Preserve

- Source原文を明示する。
- Humanの感情的・直観的反応を欠陥として削らない。
- Current Contextで意味を持つ語を保持する。

### 6.2 Isolate

- 一つの中心Themeを選ぶ。
- Supporting ConceptとSide Themeを分離する。
- 複数Themeが混在する場合、Main Themeを一つに絞り、残りはSeed候補として退避する。

### 6.3 Detect Material Delta

最低限、次を確認する。

```yaml
material_delta:
  before:
  trigger:
  after:
  newly_possible:
  avoided_failure:
  resource_reallocation:
```

### 6.4 Precisely Verbalize

AIはHumanの未言語層を、断定ではなくCandidateとして言語化する。

```yaml
precision_verbalization:
  required:
    - "中心命題"
    - "因果"
    - "守られたもの"
    - "新しく可能になったもの"
    - "回避したFailure Future"
    - "まだ分からないこと"

  style:
    - "Japanese-first"
    - "必要なEnglish Anchor"
    - "Direct Answer First"
    - "抽象→具体"
    - "一文定義"
    - "Tree when useful"
```

### 6.5 Surface Unknowns

```yaml
epistemic_layers:
  confirmed: "SourceまたはCurrent Realityから直接確認"
  inferred: "Confirmedから導くStrong Candidate"
  unknown: "Human / Field / Source確認が必要"
```

### 6.6 Build a Rebootable Thread Seed

Outputは完成Artifactではなく、専用Threadの第一Queryである。  
第一Queryは、Future AIが「何を読むか・何を深掘りするか・何をまだしないか」を復元できる必要がある。

## 7. Output Contract

生成するThread Seedは、必要に応じて密度を調整しつつ、次を含む。

```yaml
thread_seed_output:
  required:
    - "Title: 【{title}: {sub title}】"
    - "Thread identity or coordinate candidate"
    - "Source Seed"
    - "Source Context"
    - "Why this may be important"
    - "Current maturity"
    - "Mission"
    - "Open Questions"
    - "First Response Contract"
    - "Do Not Execute Yet"
    - "First Legal Move"

  optional:
    - "Related Ark concepts"
    - "Response Delta"
    - "Unexpected Success candidate"
    - "Move37 candidate"
    - "Field Test hint"
```

### 7.1 Title Rule

```text
【{title}: {sub title}】
```

- `{title}` はWorking Handle。
- `{sub title}` は何を成熟させるThreadかを一文で示す。
- Working HandleをFinal Namingとして扱わない。

### 7.2 Version Rule

Versionが必要な場合のみ記載する。

```yaml
version_policy:
  include_when:
    - "Prompt / Protocol / Artifactを識別する必要がある"
    - "複数Candidateを比較する"
    - "Field Test履歴を残す"
  omit_when:
    - "単純なTheme SeedでVersionが意味を持たない"
```

## 8. First Response Contract

新Thread AIの第一応答は、完成ではなく正しい起動を目的とする。

```yaml
first_response_required:
  - "Direct Judgment"
  - "One-Sentence Definition Candidate"
  - "Current Coordinate"
  - "Source-Preserving Restatement"
  - "Causal Spine Candidate"
  - "Confirmed / Inferred / Unknown"
  - "Unverbalized Layers"
  - "Naming Weakness"
  - "Highest-Leverage First Question"
  - "Living Review"
```

形式はMissionに応じてAdaptiveにする。  
巨大固定Templateを強制しない。

```yaml
first_response_forbidden:
  - "Final Markdown Body"
  - "GitHub Write"
  - "Canonical Naming"
  - "Large Historical Archive Excavation"
  - "Generic Advice Dump"
  - "Target Themeを置換するSide Theme Expansion"
  - "Sourceを読まずに一般知識で補完すること"
```

## 11. Stop / Hold

```yaml
hard_stop:
  - "Source Seedを特定できない"
  - "Sourceの重要Nuanceを復元できない"
  - "Human Correction / Stop"
  - "Prompt Pairが未確認"
  - "Runtime全文が確認できない"
  - "Repository / Ref / PathにMaterial Mismatch"
  - "Version Conflict"

hold:
  - "Strong ThemeかWeak Signalか不明"
  - "既存Themeとの重複可能性が高い"
  - "Target Thread coordinateが未確定"
  - "Working Nameが理解を歪めるRisk"
```

停止時は、一般知識・記憶・過去会話でSourceやRuntimeを捏造しない。
