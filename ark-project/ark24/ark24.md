# Ark24 Body Candidate — Bパターン入口AI Bridge Natural-Trigger Waiting Field

## 0. Core Thesis

Ark24は、低・超低認知状態へ入り始めるHumanへ新しい理論を説明するProjectではない。

Ark24は、高認知状態で事前形成された一つのAI Bridge Packageを、Humanが自然な入口を検知して送った時だけ、最初の身体Actionへ通せるか観測する有限Fieldである。

```text
High-Cognition Preparation
→ Frozen Query Package

Natural B-Pattern Entry
→ Human Trigger

AI Keli
→ One Route
→ One First Body Move
→ STOP

Human
→ 「完了」or Raw Actual

Ark24
→ Prediction / Actual Trace
→ Return to Ark23
```

---

## 1. Problem Structure

Ark23:01のActual Traceは、SensorとExecutionを分離した。

```text
Desire / Vision
→ desired direction remains visible

Metacognition
→ B-pattern entry is detected

Automatic Pattern
→ opposite-direction action begins

Execution Edge
→ desired first body action does not pass
```

従って、検知をさらに説明することだけではCut Edgeを越えない可能性がある。

Ark24が試すのは、DetectionとFirst Body Movementの間へ、正常時に事前計算したAI Bridge Packageを一本だけ加えることである。

このLabelの目的は、Humanを分類することではなく、介入可能なRelationを識別することにある。

```yaml

  - "medical diagnosis"

  - "whole-person identity"

```

## 4. Why Precomputed

Bパターン入口では、Humanの認知資源が低下し得る。

その場で次を要求するとBridgeではなく追加負荷になる。

```text
Explain full history
Choose among many routes
Design a prompt
Analyze the swamp
Construct a theory
```

そこで判断と文脈を高認知状態へ時間移動する。

```text
Earlier High-Cognition Self
└─ defines the label
└─ seals the query
└─ prunes the output

Later Low-Cognition Self
└─ detects
└─ sends
└─ receives one movement
```

これは`Cognitive Time Shift` Candidateである。

## 5. Boot Plane and Live Plane

```text
Boot Plane
├─ Repository binding
├─ Full reads
├─ EOF proof
├─ Pair consistency
├─ Payload non-drift
└─ waiting state

Live Plane
├─ Human trigger
├─ at most one safety question
├─ one chosen route
├─ one first body movement
├─ stop
└─ wait for 完了
```

Boot Planeの説明をLive PlaneのHuman Foregroundへ流さない。

Live Planeの一手をBoot時に試運転しない。

---

## 6. Route-Pruning Principle

低認知状態のHumanへ二Routeを比較提示すると、AIがBranchを刈らずHumanへ戻したことになる。

```text
Background Candidate Set
├─ chocoZAP Route
└─ Home Transition Route

Human-facing Output
└─ one first body movement from one route
```

AIは全Routeを説明するためではなく、現在地と実行可能性から一つへ有限化するために使われる。

不明確さが安全へMaterialな場合だけ一問する。

---

## 7. Action Granularity

Human-facing action countは一つである。

```text
Not:
  prepare → travel → workout → shower → report

Return:
  the first executable body movement only
```

一手を返した後、AIは停止する。

Humanの`完了`より先へ会話上で進まない。

このStopは、明鏡止水で行動を止める旧設計とは別である。

```text
AI output stop
= branch-control and completion wait

Human focus stop at clear state
= different hypothesis owned by Ark23
```

両者を混同しない。

## 8. Safety Gate

Workout-firstはDefault Routeであり、Absolute commandではない。

```yaml
safety_precedence:
  1: "immediate safety"
  2: "material body signal"
  3: "material sleep signal"
  4: "current feasibility"
  5: "Workout-first default"
```

AIは診断しない。

明確な停止理由がある場合、Workoutを押し通さない。

安全確認が必要なら一問だけにする。

したがって、v001のVictory Conditionを`全BパターンをAIで解決する`へ設定しない。

  - "Actual Trace"

  - "permission to improvise an unsealed substitute"
  - "proof that AI Bridge has no value"

## 12. Success, Failure, and Unexpected Success

### Package-Level Success Candidate

- Queryを送れた。
- AIが一Route・一身体動作を返した。
- Humanが一手を完了した。
- Workout Routeまたは望む方向へ接続した。
- 泥沼化前に方向転換した。
- Safety Guardが維持された。

### Package-Level Failure Candidate

- Queryを送れなかった。
- AIが長文化・多Branch化した。
- Humanが一手を実行できなかった。
- Action後も反対方向への進行が強まった。
- Safety Guardが破られた。

### Unexpected Success Candidate

Packageの当初想定と異なるが、次のPriority Pathを変える高Leverage RelationがActualから露呈した場合。

Outcomeの良さだけでUnexpected Successを認定しない。
