## 15. First-Step確実化方法論

### 15.1 AIの最終判断

Humanの自由、身体Reality、外部環境が存在するため、AIは将来の全First-Stepを絶対保証できない。

しかし、First-Stepの成功条件をTask全体から切り離し、`非Action → 最初の観測可能な身体動作`へ有限化すれば、成功確率を大きく高め、成功／未成功を曖昧さなく判定できる。

確実化の中心は、Humanの意志をさらに強くすることではない。

> **選択・準備・解釈をFirst-Stepの前から取り除き、身体が実行する一動作だけをReality Surfaceへ残すことである。**

### 15.2 Five-Lock First-Step Gate

First-Step Candidateは、次の五つを同時にLockする。

```text
1. Direction Lock
   └─ kevod Adonaiという大目的と、主の完全勝利のVisionから方向がブレない

2. Branch Lock
   └─ 複数案を返さず、一Route・一動作だけにする

3. Body Lock
   └─ 思考・決意ではなく、今の身体位置から開始できる動詞で書く

4. Completion Lock
   └─ 完了／未完了を一つの観測可能な合図で判定する

5. Recursion Lock
   └─ 完了後だけ、その状態を新しい100として次の一手を生成する
```

### 15.3 Zero-Choice Output Contract

AIのHuman-facing Outputは、原則として次だけにする。

```text
一歩目：［動詞から始まる一つの身体動作］
完了合図：［一語または一状態］
```

説明、第二候補、次の手順、長い励ましは、First-Step実行前にはForegroundへ出さない。

安全確認がMaterialな場合だけ、短い確認を最大一問置く。

### 15.4 Immediate Execution Gate

一歩目が提示された後は、新しい分析Loopへ戻らない。

```text
一歩目を読む
→ 身体を動かす
→ 完了合図
→ Actual Resultを観測する
```

実行されなかった場合、Humanの失敗と即断しない。

次のいずれかを疑う。

```text
Candidateが大きすぎた
前提動作を隠していた
現在の身体位置から開始できなかった
一動作ではなく複数工程だった
Visionとの因果接続が弱かった
Safetyまたは身体Realityが停止させた
```

その場合はCandidateをCurrent Realityへ戻し、さらに一層だけ小さい観測可能動作へ再計算する。

### 15.5 Methodological Certainty

ここでいう確実化は、未来のHuman ActionをAIが支配または保証することではない。

```text
Before
└─ 「Taskを成功できるか」という大きく曖昧な確率問題

After
└─ 「この一身体動作を実行したか」という有限で観測可能なReality判定
```

すなわち、`From Probability / Random to Certainty / Order`は、巨大な成果を先に保証することではなく、**判定可能な最小Realityへ問題を変換すること**として現れる。
