# Ark00-01: Pickup Threads

Ark00などで生まれた価値あるThreadや、繰り返し活用するThreadを選び取り、**埋もれず見つけ直し、続きを深め、再利用するためのProject**である。

このREADMEは目的・成立理由・資料の入口を所有する。設定欄へ貼り付ける指示の全文は、[INSTRUCTIONS.md](INSTRUCTIONS.md)が所有する。

## 1. なぜこのProjectを用意したか

2026-10-03 JST、YusukeJPは、Ark00: Draft White Boardが思いついた案やアイデアを自由に投げ込めるInboxとして大きく貢献している一方、Threadが多く、過去の試行や使わなくなった対話の中に、良いThreadや何度も使うThreadが埋もれると説明した。

Ark00の自由な受け皿を活かしながら、選んだ対話へ戻る場所を分ける。この役割分担をArk00-01として具体化する。Ark00全体の整理完了を待たず、価値が見えたThreadから取り上げられる。

[Ark00の既存README](../ark00/README.md)はReception・Discernment・Incubation・Routingを説明している。本Projectは、Humanが今回指定したPickupと継続利用の置き場を担う。既存のArk00を置換したり、全案に新しい通過工程を義務づけたりするものではない。

## 2. Pickupの意味とProjectの識別

Pickupは、価値や再利用の必要をHumanが認めたThreadを、大切に用いるために選び取り、取り分けることである。Humanの「聖別」という表現に込められた意味を尊重し、運用上はPickup／取り分けとして説明する。

未完成でも育てたい問い、一度でも深い価値を持つ対話、繰り返し使う実用的な対話、失敗から重要な知見を得た対話も対象になり得る。格上げは見つけやすさと利用上の扱いを変えることであり、内容全体の正しさ・完成・正本化を自動認定しない。

`Ark00-01`は複数のPickup Threadを扱うProjectの識別子であり、「Ark00の第1Thread」を意味しない。新しいMain章や章ペアの立ち上げでもない。Pickupは必要なThreadを選ぶ任意の経路として扱う。

| Node | Edge | このProjectでの意味 |
|---|---|---|
| Ark00の自由なInbox | 多様な入力を受け止める → Threadが生まれる | 発想と試行の入口を保持する |
| HumanのPickup | 価値を認めたThreadを選ぶ → Ark00-01へ取り分ける | 全件整理や一律の成熟判定を待たない |
| Ark00-01 | 選んだThreadを見つけ直す → 続きを深め、再利用する | 各Threadの本題を前へ進める |
| 実際の利用・Human Correction | 置き方や前提を見直す → 次の利用へ反映する | 使いやすさや効果は実利用から判断する |

各Threadでの通常業務は、そのThreadの本題を続けることである。毎回の選抜審査や管理作業に置き換えない。文脈、重要な訂正、試行の経緯、再開地点もThreadの価値に含める。
