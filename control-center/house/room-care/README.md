# Room Care — 居室の片付け・清掃・整理整頓

**YusukeJPが大切にしているAI活用を、居室の現実改善へ接続する。** 写真と対話を入口に、Humanが実際に片付け・清掃・整理整頓を行い、結果から方法を育てる。整えた状態の維持と、使いやすさの改善も含む。

ここは実践の目的・形成理由・判断・方法の所有資料。[Ark109: room-care](../../../ark-project/ark100-199/ark109_room-care/README.md)はその協働を続ける専門Projectの入口であり、Project指示と起動条件を所有する。保存先がGitHubでも、対象は物理的な居室である。

## 1. Humanが変えようとしていること

以下は準備対話の編集要約であり、逐語録ではない。

Humanは、休日の時間と労力をほぼAI活用へ注いでおり、「片付けに使える時間があるならAI活用へ向かう」という行動原理のため、居室の片付けの優先順位が著しく下がっていると説明した。一人で片付け・整理整頓を試みても難しかった、という報告もある。これは現在までの経験の報告であり、永久に一人では不可能という判定ではない。

そこで、AIへの関心を居室の改善にも活かし、AIと相談する時間から現実の行動へ接続したいと考えた。Human自身が居室を撮影し、画像を基にAIとコミュニケーションしながら取り組む、新しい分野への挑戦である。AIの活用、居室の改善、協働方法の発見がつながる**複数問題同時解決**を目指す。

AI側の役割は、写真や説明から状況・関係・選択肢を読み解き、Humanの意図を共有できる言葉と実行可能な提案に変えること。物理的な作業、使いやすさの実感、重要な判断とFinal SealはHumanが保持する。会話や資料だけが増え、居室へ変化が届かない場合は、その接続にBottleneckがある可能性として見直す。

## 3. Graph Modeで見る関係

| Node | Edge | 判断への意味 |
|---|---|---|
| AI活用への関心 | 写真・対話 → 居室の理解と行動案 | Humanが元々向けている時間・労力を、room-careにも接続する |
| 物・場所・用途 | 使用頻度・動線・取り出し方・戻し方 | 見た目だけでなく、使いやすさと維持できる配置を考える |
| Humanの現在 | 希望・時間・体調・Guard → 今扱う範囲 | 実行か検討か、どこまでかを現在の入力から選ぶ |
| 写真と説明 | 観察・補足・訂正 → 共有した状況理解 | 写真に写らない事情をAIの推測で埋めない |
| Humanの行動と報告 | 実際の変化 → 次の判断 | 進捗と使いやすさを別々に確かめ、方法を修正する |
| 学び | 条件付きの経験 → 後の協働 | 一件の成功・失敗を過大一般化せず、再利用できる根拠を残す |

これは決まった儀式や毎回の出力Templateではない。整理整頓→レイヤー構造→関係構造化→interface化を必要に応じて使い、画像・説明・表・短い手順など、今の理解と行動に役立つ形を選ぶ。Humanの手元へ不要な同時Taskを増やさず、AIの分析品質は保つ。

## 4. 初回から使える協働方法 — 実践候補

以下は目的に沿ったAIの方法提案であり、豊富な検証を終えたBest Practiceではない。具体的なHuman入力で選び直せる。

**受け取る。** 写真、言葉での困りごと、片付けたい場所、途中経過のどれからでも始められる。既に示された入力を受け取り、全室撮影・詳しい棚卸し・同じ説明のやり直しを条件にしない。

**理解する。** 実際に見える状態とHuman報告を土台にする。例えば「床に物がある」という観察と、「通行の負担になっている」という推測を分ける。Humanが大切にしている物、日常の使い方、置けない理由など、判断を変える不足だけを確認する。

**つなぐ。** 今は実行するのか、配置を比較するのか、言語化を深めるのかを現在の意図から選ぶ。実行を望む場合は、対象・終了の目安・止める条件が分かる範囲へまとめる。小ささ自体を絶対ルールにせず、時間・体調・希望に合う適切な範囲を提案する。

**確かめる。** Humanの実行報告や必要に応じた写真から、何が変わったか、使う／戻す負担はどうかを聞き取る。追加写真を必須にしない。写真で見える変化と、Humanの体感や維持できた期間を混ぜない。完了、途中、保留、中断のいずれも現在地として扱う。

**育てる。** 役に立った理由・成立条件・残る困りごとを次へ戻す。記録する場合は、現在の依頼と権限に沿って必要なものを保存する。初回から専用台帳、全物品Database、Skill、全室Planを作ることをGoalにしない。

片付けは物を収める判断、清掃は汚れ等への対処、整理整頓は必要性・置き場所・取り出しやすさ・戻しやすさの関係、維持は普段の流れとの接続として、今回必要な部分を扱う。全てを一度に完成させる必要はない。

## 5. Guardと権限

Root・Teshuvah・Human Foreground One・Human Authority・AI品質は[AGENTS](../../../AGENTS.md)と[ARK](../../../ARK.md)を保持する。居室の状態を人格・信仰の評価へ置き換えず、Humanの心中や主の御心を断定しない。

写真から物の所有、不要性、材質、隠れた状態や安全性を確定しない。捨てる・購入する・外部へ依頼する等は、Humanの現在の意図・権限を確認する。身体・睡眠・安全Guardが判断を変える時は、その範囲を調整する。重大な危険がある場合は該当作業を止め、適切な対応へ接続する。

会話内で受け取った写真は、そのままGitHubに保存・公開する許可ではない。画像や個人情報の外部保存は対象と公開範囲を確認し、成果文書には目的に必要な根拠を残す。新しいRepositoryは作らない。現在の受入れや資料整備だけで撮影・片付け・身体Trial・他Taskを自動開始しない。
